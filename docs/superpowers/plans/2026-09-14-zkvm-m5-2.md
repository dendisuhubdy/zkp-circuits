# Rand zkVM M5.2 — the recursion VM's machine: AIRs, traces, prover, verifier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn M5.1's semantics into a proving machine. The `recursion/` crate gains `tables/` (eight AIRs — cpu, two memory tables, a permutation-per-row Poseidon2 chip, a preprocessed program table, a public table, a range table, and an optional per-proof reduction chip), `machine.rs` (batch prover/verifier, tiers, a program-dependent verifier-key cache, mirroring `research/src/machine.rs`), and the cheating-test suite that proves each table's soundness argument. The exit test proves the M5.1 verifier program's execution over **one real constraint-set-6 production-profile bundle proof** and verifies that rVM proof natively. The measured numbers the plan is cut from — 5 682 847 cpu rows per inner proof, 2^22.44 — force three things the spec did not anticipate, and this plan rules on them rather than discovering them mid-implementation: the program table must be **preprocessed** (an in-circuit program digest costs one Poseidon2 permutation per instruction = 5.69 M permutations, a 2^23-row hash table — impossible), the tier ladder is re-cut to `[8, 10, 12, 14, 16, 18, 19, 20, 21, 22]` with the exit at **tier 21**, and reaching tier 21 takes the row cuts M5.1's Task-7 analysis named: DSL allocator liveness plus two measured-gate precompiles (`REDUCE`, `SPONGE`), staged as their own tasks with differential tests against the compiled sequences they replace.

**Architecture:** The rVM is proved with exactly the RV32 machine's batch-STARK stack — same Goldilocks field, same degree-2 extension, same Poseidon2 permutation and round constants, same `HidingFriPcs` profile (`log_blowup 3`, 80 queries and 20 PoW bits at production, arity ≤ 8, cap height 2), same `p3-lookup` bus machinery — over a new, much smaller table set. The machine's skeleton (`machine.rs`) is `research/src/machine.rs` rewritten for this chip set: the same `Config` aliases (imported, not re-derived), the same `Tier`/`TIERS` discipline, the same proof-declared heights with range checks, the same `key_config`/`make_config` entropy split, the same FIFO key cache. What is genuinely new: the program table is a **preprocessed** trace (the RV32 machine's pre-M3.4 shape, correct here because the rVM's program is a public registered artifact, not a private guest), which makes the rVM verifier key program-dependent and removes the in-circuit `hc` digest entirely; registers are cells `2^24 + k` on a register memory table, a second instance of the one memory AIR (there is no register file in the cpu row, and no 32-entry one-hot anywhere); and the machine's public interface is always exactly four field elements — the in-circuit-computed digest of whatever the program chooses to commit — the `verify_public`/`H_PUB` pattern the RV32 machine already ships for constraint set 6. The verifier program itself changes in two places, sequenced before the exit: its public phase becomes store-sponge-publish-digest (ruling R5), and it picks up the two precompile instructions (Tasks 8, 9) behind the same measurement gates M5.1 used.

**Tech Stack:** Rust 1.98.1, Plonky3 0.7 exactly as `recursion/Cargo.toml` already pins it, plus `p3-dft = "=0.7.0"` (the one dependency M5.1 did not need and the prover does — `Radix2DitParallel`). No other new crates, no CUDA, no RISC-V target. `rand_zkvm` stays a path dependency: the rVM imports its `Config` aliases, its `FriProfile`, its Poseidon2 reference (`hash::permute_state`, `tables::poseidon2::{round_constants, permute_scalar, mds_light, internal_matmul, cube}` — all `pub`), its `Program`-digest construction for the rVM program's own digest, and the M5.1 fixtures (bundle proofs, the ledger) for the exit.

**Spec:** `docs/superpowers/specs/2026-09-13-zkvm-m5-recursion-vm-design.md` §2 (crate layout), §3 (the ISA), §5 (tables/buses/proof shape — amended here at four points, each flagged in the rulings table), §7 (M5.2's milestone text and exit test; its cost model is replaced by the M5.1 measurement, as §7 itself instructs), §8 (testing), §10 (rulings inherited), §11 (the verifier-key open item — closed here, ruling R6). The measurement: `recursion/docs/00-recursion-vm.md` (every row count below is from it unless explicitly labelled an estimate). The template: `docs/superpowers/plans/2026-09-13-zkvm-m5-1.md` (structure, TDD discipline, the Task-7 precompile pattern Tasks 8–9 reuse). The machine being mirrored: `research/src/machine.rs`, `research/src/tables/`, `research/tests/cheating.rs`, `research/AGENTS.md` (invariants 1–3, the `rejects()` discipline, commit style, docs-carry-measured-numbers).

## Global Constraints

### Where the code lives and how it is run

- Everything lands in `recursion/` (`src/tables/`, `src/machine.rs`, new test files), the package root M5.1 established; `research/` is **not edited** by this plan (M5.1's only two `research` touch-points — the exposed `log_ext_degrees` and the test hooks — are already merged). Every cargo command runs from `recursion/` with the crate's own pinned toolchain: `cargo +1.98.1 test -p recursion --test <suite> <name> -- --exact`.
- Commit style per `research/AGENTS.md`, crate-prefixed: **`recursion: <area> — <what>`**, one logical change per commit, docs riding with the change they describe.
- `recursion/Cargo.toml` gains exactly one line: `p3-dft = "=0.7.0"` (Task 1).

### The measurement this plan is written against

M5.1's measured cost of verifying **one real cs6 production-profile bundle proof** in the rVM (`recursion/docs/00-recursion-vm.md`, pinned by `tests/pins.json`; 9 instances, degree bits `[13,15,17,16,9,9,17,11,3]`, arity schedule `[1,1,2,2,2,3,3,3]`):

| | `FriProfile::Test` (16 q) | `FriProfile::Production` (80 q) |
|---|---:|---:|
| cpu rows | 1 209 871 | **5 682 847** (= 2^22.44, over spec §5's `TIERS` top of 2^22) |
| Poseidon2 permutations | 11 195 | **51 595** (fits 2^16 = 65 536) |
| memory accesses | 1 365 013 | 6 354 037 |
| program instructions | 1 211 914 | 5 692 650 |
| witness words | 43 344 | 199 760 |

Where the production rows go (measured): the FRI query phase is 5 109 772 rows, of which the batch-opening reduction over **1 952 opened columns per query** (main 1 084, random 54, quotient chunks 408, preprocessed 42, permutation 364) is ≈ 2.8 M with its spill traffic (~50 % of the total); Merkle work ≈ 1.3 M; `sample_bits` ≈ 94 k; folds ≈ 100 k. The allocator spilled **1 525 260** handles and reloaded **929 251** of them (cs6; 2 454 511 spill/reload rows = 43 % of all cpu rows). `FRIFOLD`/`EXPBITS` were measured at ~3 % combined and are **not** built (M5.1's Task-7 analysis, which this plan does not reopen).

Every number in this plan is either one of these measured values or an explicitly labelled estimate with its derivation shown (the sizing section is the only place estimates are load-bearing, and Task 10 replaces them with measurements).

### The frozen inputs (M5.1's handoff, binding)

- **The ISA is frozen at 24 instructions with a pinned encoding** (`recursion/src/isa.rs`); new opcodes are only ever **appended** (Tasks 8–9 take 24 and 25; opcodes 0–23 never move), and every program digest changes when the program changes — sequenced strictly before Task 10's exit proof.
- **The emulator is the reference semantics**: if an AIR and `recursion/src/emulator.rs` disagree, the AIR is wrong (the `research/AGENTS.md` rule, transferred by M5.1). Every trace builder consumes `emulator::Execution` events; every event field the tables need (`pc`/`next_pc`, the three operand pairs, the timestamped `MemAccess` log at `16·clk + k`, the `PermEvent`) already exists.
- **The verifier program is pinned**: 50 real production-profile bundle proofs accepted, 50 tampered refused at named checkpoints; in-suite twins at the test profile. When M5.2's prover hits a constraint failure, the witness is not in question.
- **Reuse vs rebuild** (spec §5's ruling, unchanged): the field, the extension, the Poseidon2 parameters + reference permutation, the FRI profile, the batch-STARK configuration and the lookup-bus machinery are *reused* from `rand_zkvm`; the tables and the machine are *new* code in `recursion/`. The RV32 machine's tables are never touched.

### Testing and docs discipline (inherited)

- Cheating tests use **`rejects()`** (`research/tests/common/mod.rs`'s definition, re-homed in `recursion/tests/common/mod.rs` by Task 1): a per-instance constraint-checker panic (`CONSTRAINT_PANIC`), a global lookup-balance panic (`LOOKUP_BALANCE_PANIC`), or a verify error — and nothing else — counts as a rejection. The crate's `[profile.test]` keeps `debug_assertions` on (the AGENTS.md warning about `--release` weakening `rejects()` applies here unchanged).
- All green is the bar before any commit. Measurements that cost minutes are `#[ignore]`d with the measured wall time and the machine requirement in the ignore message (the house pattern: `research/tests/e2e.rs`), each with a fast in-suite twin.
- Docs carry measured numbers: widths, degrees, rows, tiers, proof size, prove/verify time, test counts. Task 10 writes them into `recursion/docs/01-rvm-machine.md` and refreshes `recursion/docs/00-recursion-vm.md` for the ISA and pin changes.

| R1 | **The program table is preprocessed** (4 preprocessed word columns + 3 witness columns), committed by the verifier key's preprocessed cap; there is **no in-circuit program digest** | The spec's construction ("committed in the program table exactly as the RV32 machine's `hc`") is one Poseidon2 permutation per instruction; at the measured 5 692 650 instructions that is 5.69 M extra chip rows — a 2^23-row, ~340-column hash table whose committed oracle alone is ~370 GB, nearly three times the rest of the exit proof's oracle combined. The rVM's program is a *public registered artifact* (spec §2: the fullnode registers its digest), so the RV32 machine's M3.4 reason for moving the program into the witness (program hiding) does not exist here. Spec §5's own phrase — "exposed in the verifier key" — is exactly what a preprocessed table means. **Spec amendment 1.** | If the program ever needs hiding, the digest construction comes back with a wider-rate hash and the poseidon2 budget is re-cut — a new constraint-set decision, not a silent regression. The verifier key being program-dependent means one key build per (program, tier): measured and cached (Task 2). |
| R2 | **`TIERS = [8, 10, 12, 14, 16, 18, 19, 20, 21, 22]`**; the exit targets **tier 21**; there is deliberately no 23 | Spec's `[14,16,18,20,22]` is obsolete at the measured 5 682 847 rows (2^22.44). The ladder: 8–18 at stride 2 for cheap unit/DSL proofs (the RV32 house style); **19** — the test-profile verifier program after the row cuts (est. ~0.3–0.5 M rows); **21** — the production exit after the cuts (est. ~1.4–2.0 M rows against 2^21 = 2 097 152); **22** — the safety rung if the cuts land above 2^21 (at ~2× the memory, recorded). | R3 | **Row-cut strategy: (d) — liveness first (Task 7), then the `REDUCE` (Task 8) and `SPONGE` (Task 9) precompiles, each gated on a re-measurement** | Baseline: 5 682 847 rows → tier 23 → ~165 GB peak (rejected). Both are expected to run; the ISA/digest changes land strictly before Task 10. | Without the gates the ISA churns on a guess; without the cuts the exit needs ≥ 96 GB and this plan has no machine. The estimates are marked; Tasks 7–9 re-measure and Task 10 records the truth. |
| R4 | **Registers are memory cells `2^24 + k` on a register memory table** — a second instance of the one memory AIR, on its own `REG` bus; RAM stays below `2^24` on the `RAM` bus | The alternative — a 32-register file in the cpu row — needs the 32 file columns plus three 32-wide one-hot masks (read ra, read rb, write rd): cpu width ~180, at 2^21 that is ~50 GB of committed oracle against ~34 GB for the bus design (cpu ~18 GB + register table ~16 GB) — strictly worse. Putting register traffic on the *same* table as RAM merges ~5.4 M register messages with ~3.9 M RAM messages ≈ 9.3 M → one 2^24 table (~32 GB of oracle); split, the register table holds ~5.4 M → 2^23 and RAM ~3.9 M → 2^22, ~24 GB together, saving ~8 GB. The ISA's two namespaces (register index vs cell address) are preserved: register messages are built from the 5-bit-range-checked index, RAM messages from the 3-byte-limb-checked address, and each bus balances independently, so neither table can answer for the other's messages. | The one-hot design was the cpu-width blow-up the spec's "~50" feared; the merged-table design pays ~8 GB of oracle for one fewer bus and one fewer instance. The split is two instances of one AIR — no new AIR code, one extra bus. |
| R5 | **The batch public values are always exactly 4 field elements: the in-circuit digest of the program's public interface** (`RVM_PUB_DOMAIN = 17`); the verifier program's phase 8 stores the §4.4 list, sponges it, and `PUBLIC`s the digest | A variable-length public list (`5 + 34·N` values) cannot be a batch public-value vector at all (the count is a static AIR property), and a raw 39-value list needs ~78 selector columns to tie it to the trace — 554 columns at N = 8 in M5.3, ~350 kB of proof. ## The tables and buses (the design the tasks implement)

Widths below are **designed estimates** derived from the ISA's real operand counts and the RV32 tables' column arithmetic; each task pins its table's `col::WIDTH` and max constraint degree by test (the `research/tests/tables.rs` pattern), and Task 10 records the pinned values in `recursion/docs/01-rvm-machine.md`. Every table's trace builder consumes `emulator::Execution` events; "boundary" constraints are `when_first_row`/`when_last_row`, "transition" is `when_transition`, in the RV32 tables' idiom.

### `program` — preprocessed 4 + witness 3, height `pad_height(len + 1, 4)`

- **Columns.** Preprocessed: `W0..3` — the four encoded words of the instruction at this row (`Program::encode`), built by `ProgramAir::preprocessed_trace` from the registered program. Witness: `IDX` (row index, the `pc`), `IS_REAL` (boolean, real rows a prefix), `MULT` (fetch count).
- **Constraints.** `IDX` starts at 0 and increments by 1 every row, padding included (the `tables::public.rs` pattern — harmless on padding, which nothing reads); `IS_REAL` boolean and prefix-forming; `(1 − IS_REAL)·MULT = 0` (**invariant 2**). No in-circuit decoder: the preprocessed trace is verifier-built from the registered program, so word legality is a *registration-time* host check (`Machine::check_program`, Task 2) — the M3.4 panic-on-undecodable invariant moved to the one place the words enter the machine.
- **Bus.** Provides `PROGRAM [IDX, W0..3]` with count `MULT`. The cpu consumes exactly one fetch per real row. The message's `pc` is `IDX`, so the registered program's instruction `i` is the only provider for `pc = i` — a wrong program word is a different preprocessed commitment, i.e. a different verifier key, not a lookup failure.
- **Cheating tests.** A proof of program A never verifies against program B's key (the cap differs — the RV32 `proof_for_one_program_does_not_verify_another` analogue, spec §7's "bad program digest"); a fetch-count tamper (`MULT` short by one) unbalances `PROGRAM`.

### `cpu` — `col::WIDTH ≈ 64`, height `2^tier`

- **Columns.** Control: `CLK`, `PC`, `NEXT_PC` (3). Fetch: `W0..3` = `OP`, `RD`, `RA`, `B` (4), consumed on `PROGRAM` as `[PC, OP, RD, RA, B]`, count `IS_REAL`. Decode: 24 one-hot opcode selectors (24) — each boolean, sum `= IS_REAL`, `Σ k·sel_k = OP` (which also proves `OP ∈ 0..23`; selectors gain two entries in Tasks 8–9). Operands: `A0 A1` (the `ra` pair), `B0 B1` (the `rb` pair, or `[imm, 0]`), `D0 D1` (the `rd` result pair — or the compared/stored value for `JEQ`/`JNE`/`STORE*`) (6). Register-index range bits: `RD`/`RA`/`RB` 5-bit decompositions (15) — each bit boolean, the index equals its bit sum (gated on `b_is_register` for `RB`); this is what makes every register-bus address `2^24 + idx` with `idx < 32`, and it *is* the `rd, ra, rb < 32` decode check the emulator performs. Address limbs: two 3-limb groups (6), every limb a `RANGE8` lookup. Group 1 proves the row kind's primary address subject `< 2^24`: `A0 + B + {0,1,7}` for `LOAD`/`STORE`/`LOADE`/`STOREE`/`POSEIDON2`/`SPONGE`'s state pointer, `B` for a taken branch target. Group 2 proves `SPONGE`'s source pointer `B0 + 3`, gated on `IS_SPONGE` — the one row kind with two addresses. Gadgets: `rd`-is-zero (2, the `alu.rs` two-constraint pattern — the `r0` write-drop), branch-equal (2, is-zero of `D0 − A0`). `PUB_IDX` (1): the running count of `PUBLIC` rows, `+1` on `PUBLIC`, boundary 0. `IS_REAL` (1).
- **Constraints.** Boundary: row 0 has `CLK = 0`, `PC = 0`, `PUB_IDX = 0`, `IS_REAL = 1`; padding is a suffix; the last real row is `HALT` with `NEXT_PC = PC`. Transition: `CLK + 1`; `PC' = NEXT_PC` on real rows. Per-opcode semantics gated by the selectors, mirroring `emulator.rs` case by case: base arithmetic `D = A ∘ B`; extension arithmetic over the pairs (`EMUL`: `D0 = A0·B0 + 7·A1·B1`, `D1 = A0·B1 + A1·B0` — the `BinomialExtensionField<Goldilocks, 2>` multiplication, `X² = 7`); `INV`: `A0·D0 = 1`; `EINV`: the two-component product is `(1, 0)` — the hint-and-check shape, unsatisfiable at zero, which is what makes the DSL's assertion traps unprovable at the machine level too; control: `NEXT_PC = B` when the branch is taken (the equal gadget deciding), else `PC + 1`; `HALT`: `NEXT_PC = PC`.
- **Buses (all sends; invariant 1: every message's address/value columns are the constrained operand and index columns above, on every row kind that sends; invariant 2: every count is a selector expression, 0 on rows that do not perform the access, and all are 0 on padding rows).** `REG [2^24 + idx, ts, value, is_write]`: read `ra` (+`ra+1` for extension ops), read `rb` (+`rb+1`) when `b_is_register`, read `rd` for `JEQ`/`JNE`/`STORE*`, write `rd` gated by the write-op selectors times `(1 − rd_is_zero)` — the `r0` drop, and the reason a read of cell `2^24` always returns 0 (never written: the first-touch rule) — and write `rd+1` gated only by the extension-write selectors (an `E0` write lands in `r1`, exactly the emulator's `set_pair`). `RAM [addr, ts, value, is_write]`: the `LOAD`/`STORE`/`LOADE`/`STOREE` accesses, addresses limb-checked. `POSEIDON2 [CLK, ptr]`, count `IS_POSEIDON2`; `SPONGE [CLK, A0, B0]`, count `IS_SPONGE` (Task 9); `REDUCE [CLK, descr_ptr]`, count `IS_REDUCE` (Task 8). `PUBLIC [PUB_IDX, A0]`, count `IS_PUBLIC`. `RANGE8`: the six address limbs, counts gated by the row kinds that form an address. Timestamps are `16·CLK + slot` with a constant slot per message, matching the emulator's `MemAccess` log exactly.
- **Cheating tests** (spec §7's cpu items): a wrong arithmetic result (tampered `D`), a broken pc chain (a skipped row), a bad `INV` hint (`D ≠ A⁻¹` — `A·D ≠ 1`), an address ≥ 2^24 with the limbs forged (a `RANGE8` imbalance), a register write to `r0` surfacing as a nonzero `r0` read (the `rd_is_zero` gate), a padding row with a nonzero send count (invariant 2). Each is a `rejects()`.

### `reg_memory` and `ram_memory` — one `MemoryAir`, two instances, `col::WIDTH = 11`

- **Columns.** `ADDR`, `TS`, `VALUE`, `IS_WRITE`, `IS_REAL`, `ADDR_CHANGED`, `DIFF_INV`, `D0..D3` — `research/src/tables/memory.rs` minus `SPACE` (the register/RAM split carries the space in the address and the bus, not a column).
- **Constraints.** Verbatim the RV32 memory table's: sorted by `(ADDR, TS)`; the `ADDR_CHANGED`/`DIFF_INV` pair pinning "changed ⇔ keys differ"; the delta between consecutive keys (address delta − 1, or timestamp delta − 1 within one address) equal to the four `D` limbs, each a `RANGE8` lookup gated on both rows real; read-after-write (same address, a read returns the last written value); first touch of a fresh address as a read returns zero (boundary + transition). The register table's addresses are `2^24 + k`, `k < 32`; the RAM table's are `< 2^24`; neither table constrains its address range itself — the *senders* do (cpu's 5-bit index decompositions and 3-byte limbs), and a row planted in the wrong table is an unclaimed supply on its bus (**invariant**: each bus balances independently).
- **Heights.** Proof-declared `reg_log_height` / `ram_log_height`, range-checked against `[4, 26]`, exactly the RV32 `Proof::mem_log_height` argument (one-sided: a prover can only oversize, which wastes their own time; undersizing leaves accesses with nowhere to balance). Expected values at the exit: 23 (≈ 5.4 M register messages) and 22 (≈ 3.9 M RAM messages, chip traffic included).
- **Cheating tests.** A tampered `VALUE` (the "wrong Merkle sibling" and "wrong fold value" items — the program's own checkpoint traps the execution, and the trace-level tamper is a read-after-write violation), a first-touch nonzero read, a delta-limb forgery, a same-timestamp double access.

### `poseidon2` — permutation-per-row, `col::WIDTH ≈ 340`, height `pad_height(perms + 1, 16)`

- **Columns.** `IS_REAL`, `MULT` (pinned `= IS_REAL`), `CLK`, `PTR`, `SRC_PTR`, `IS_PERM`/`IS_SPONGE` row-kind selectors (Task 9 adds the second kind), `IN0..7` (the permutation input), 29 intermediate round states × 8 (`R1..R29`), `OUT0..7`, and S-box intermediates: 8 full rounds × 8 `X3` lanes + 22 partial rounds × 1 = 86. The 30 rounds are unrolled inside `eval` with the round constants as literals (R9).
- **Constraints.** `X3 = (S + rc)³` and `S_next = mds_light(X3·X3·(S + rc))` on full rounds, `internal_matmul` with the lane-0-only S-box on partial rounds — every constraint degree ≤ 3, the same split as `research/src/tables/poseidon2.rs`, whose `mds_light`/`internal_matmul`/`cube` helpers and `round_constants` draw it imports and whose reference (`permute_scalar`, bit-identical to `Poseidon2Goldilocks<8>::permute`) anchors the equality contract. `IN` is the bus-tied input: for `IS_PERM`, the eight cells at `PTR`; for `IS_SPONGE`, the four cells at `SRC_PTR` in lanes 0–3 and the four cells at `PTR + 4` in lanes 4–7 (the absorb-overwrite, Task 9).
- **Buses.** Provides `POSEIDON2 [CLK, PTR]` count `IS_PERM` and `SPONGE [CLK, PTR, SRC_PTR]` count `IS_SPONGE`. Sends its own `RAM` messages — the keccak/sha256 pattern: 8 reads + 8 writes for `IS_PERM`, 4 + 4 + 8 for `IS_SPONGE`, at `ts = 16·CLK + slot`, so the permutation is tied to real memory, and `(clk, ptr)` is only the handle (**invariant 1**: the message values are the constrained `IN`/`OUT` columns).
- **The equality contract (spec §7).** A test drives a program that permutes 1 000 random states (and, after Task 9, sponge-absorbs 1 000 random buffers) and asserts, in-program against `HINT`-supplied reference outputs (`hash::permute_state` computed host-side), that the chip's `OUT` equals the reference — the proof verifies iff chip = reference on all 1 000; the tampered-twin refuses. Plus the trace-level unit test (`OUT == permute_scalar(IN)` over the built trace) and the constants-draw test (the literals equal `round_constants()`).
- **Cheating tests.** A skipped permutation (a dispatch with no chip row: `POSEIDON2` supply short — `LOOKUP_BALANCE_PANIC`), an extra permutation (a real chip row nothing dispatched), a wrong `OUT` (round constraints), an `IN`/`OUT` value that disagrees with memory (`RAM` balance).

### `public` — `col::WIDTH = 7`, height 8; owns the batch's 4 public values

- **Columns.** `IDX`, `VALUE`, `IS_REAL`, and the 4-slot selector tie from the RV32 cpu's `OUT_SEL` pattern: `SEL0..3` (4).
- **Constraints.** `IDX` = row index (boundary 0, `+1` per row); `IS_REAL` boolean, prefix; on real rows exactly one `SEL_i` is set, gated `SEL_i·(IDX − i) = 0`, pinning `VALUE = pv[i]` for that slot; on padding rows no `SEL_i` is set (their sum is `IS_REAL`). The RV32 pattern's never-written arm cannot arise — the interface digest is always exactly 4 words, so all four slots are always selected — and no `WRITTEN` accumulator is needed. `num_public_values = 4` — constant, program-independent (R5: every rVM program publishes exactly its 4-element interface digest).
- **Bus.** Provides `PUBLIC [IDX, VALUE]` count `IS_REAL`; the cpu consumes one per `PUBLIC` instruction with its `PUB_IDX` counter. Set equality then forces: the values the program published, in order, are exactly the proof's four public values.
- **Cheating tests.** A forged public value (tampered batch pv → native verify's digest compare fails; tampered `VALUE` → `PUBLIC` imbalance or the selector constraint), a published value out of order, a fifth `PUBLIC` (no provider).

### `range` — 256 rows, mirrors `research/src/tables/range.rs`

Preprocessed `VALUE` (0–255) + witness `MULT`; provides `RANGE8` to the cpu's address limbs and both memory tables' delta limbs. Fixed height, no declared parameter, identical every key.

### `reduce` (Task 8; optional per proof, `reduce_log_height == 0` = absent) — `col::WIDTH ≈ 20`, height `pad_height(rows + 1, 4)`

- **Role.** One chip row per reduction column: `acc += alpha_pow · (pz − lift(px)) · inv`, `alpha_pow ·= alpha`, reading `pz` (extension, two cells) and `px` (base, one cell) from memory. Replaces the compiled inner loop of `emit_reduced_openings` (post-liveness est. ~7 cpu rows per column × 156 160 column-terms ≈ 1.1 M rows) with 156 160 chip rows.
- **Columns.** `IS_REAL`, run-boundary selectors `IS_FIRST`/`IS_LAST`, `CLK`, `DESCR_PTR`, the carried chain `ACC0/1`, `APOW0/1`, the run constants `INV0/1`, `ALPHA0/1`, the read values `PZ0/1`, `PX`, and the incrementing addresses `ADDR_V` (+2/row), `ADDR_R` (+1/row).
- **Constraints.** `ACC' = ACC + APOW·(PZ − PX)·INV` and `APOW' = APOW·ALPHA` (extension arithmetic, degree 3); the addresses step within a run and restart at the descriptor's bases on `IS_FIRST` (read from memory: 11 descriptor cells); on `IS_LAST` the chain is written back to the descriptor's `acc`/`apow` slots (4 cells) for the next `REDUCE` of the same height group. The per-run semantics is exactly the compiled sequence's (the differential test, Task 8).
- **Buses.** Provides `REDUCE [CLK, DESCR_PTR]` count `IS_REAL·IS_FIRST` (one entry per run, on its first row — the sha256 block pattern). Sends its own `RAM` messages (3 per row + descriptor I/O at the boundaries) at `ts = 16·CLK + slot`, distinct slots per message, distinct timestamps across runs by `CLK` — the memory table's per-address monotonicity is preserved.
- **Cheating tests.** A wrong accumulated value, a dropped column (run length short by one: `RAM` supply/demand and the chain's boundary), a forged descriptor field, a `REDUCE` dispatch with no chip run (bus imbalance).

## Sizing: tiers, the exit-proof memory model, the row-cut arithmetic

### The memory model (estimate, calibrated, replaced by Task 10's measurement)

For a batch instance of height `2^h` and width `w`, the dominant resident structure is the committed oracle: the ZK-doubled matrix at `2^(h+1)` rows, LDE'd at blowup 8 → `2^(h+4) · (w + 4 random codewords) · 8 bytes`. Summed over instances, plus ~25 % for quotient chunks, LogUp permutation traces, FRI trees and working set. Calibration: the model gives ~30 GB for the RV32 tier-18 EVM batch (cpu 2^18 × 275, keccak, etc.); the measured floor is ≥ 28.5 GB resident at SIGKILL and still growing, with ≥ 64 GB the documented requirement (`research/docs/04-guests.md:349`). Estimates below use `peak ≈ 1.25 · Σ oracle`.

### The three scenarios (production profile, per inner proof — the exit proof)

| scenario | cpu rows | tier | oracle sum | peak (est.) | machine |
|---|---:|---:|---:|---:|---|
| no cuts | 5 682 847 | 23 | ~132 GB | **~165 GB** | ≥ 192 GB — **rejected**, no such machine |
| liveness only (est. −2.1 M) | ~3.6 M | 22 | ~68 GB | **~85 GB** | ≥ 96 GB — **rejected** as the target |
| liveness + `REDUCE` + `SPONGE` (est.) | ~1.9–2.0 M | **21** | **~48 GB** | **~55–65 GB** | **≥ 64 GB — the plan** |

Tier-21 oracle breakdown (the R3 scenario, widths from the design section): cpu `2^25·68·8` = 18.3 GB; reg_memory `2^27·15·8` = 16.1 GB; ram_memory `2^26·15·8` = 8.1 GB; poseidon2 `2^20·345·8` = 2.9 GB; program `2^25·7·8` = 1.9 GB (plus the ~0.3 GB native preprocessed tree per key build); reduce `2^22·24·8` = 0.8 GB; public/range negligible. Σ ≈ 48.1 GB.

**Does it fit 48 GB? No — stated plainly (R10).** The exit's in-suite twin (test profile, est. ~0.3–0.5 M rows → tier 19, ~11–14 GB peak) runs on the 48 GB development machine; the production exit is `#[ignore]`d with the ≥ 64 GB requirement and its command, exactly the tier-18 EVM precedent. The follow-up levers toward 48 GB, recorded not planned: paired register messages on `REG` (one message per aligned pair; ≈ −7 GB of oracle, at the cost of a lane-masked memory AIR), and further ISA-level cuts toward tier 20 (`HINT4`, a `MERKLE` selector-compress — each needs its own measurement first).

### Proof size and verification cost (estimates, derivation shown; measured in Task 10)

- **Proof size ≈ 0.5–0.6 MB** at the exit tier, production profile. Derivation: opened row values dominate — ~640 columns per query (main ~458 + salt/hidden ~40 + quotient ~50 + preprocessed 5 + permutation ~25 + random ~64) × 80 queries × ~8 B/column-query, the per-column cost calibrated from the measured bundle proof (330 620 words ≈ 1.32 MB at tier 14 with its ~1 900–1 952 opened columns per query) ≈ 0.41 MB, plus claimed evaluations (~10 kB), commitments (~2 kB), FRI commit-phase openings and pruned multiproof paths (~0.15 MB). The fullnode's 2 MiB cap holds with ~3.5× headroom; the poseidon2 chip's ~340 columns are over half of the per-query opened values — the price the spec's permutation-per-row ruling pays for a 3.6×-smaller table, and R9 keeps its constants from adding ~150 kB more.
- **Verify cost:** key build is the new term — the 2^22-row preprocessed program tree, est. 3–6 s once per (program, tier), then cached; batch verify est. ~1–2 s cold, ~20–30 ms warm (FRI at `log_global_max_height` 28 vs the bundle proof's 20). One call per sealing block, unchanged from spec §5's expectation.
- **Prove time:** est. 20–40 min at the exit tier (≈ 5.9 G oracle cells at the calibrated 4–6 M cells/s of this hardware), `#[ignore]`d; the tier-19 twin est. 2–5 min in-suite.

## What M5.2 hands to M5.3

- **The prover API `aggregate()` calls** (`recursion/src/machine.rs`): `Machine::new(FriProfile::Production)`, `Machine::prove(&program, witness_tape, tier) -> Result<(Proof, Execution), ProveError>`, `Machine::verify(&program, &proof) -> Result<(), VerifyError>`, and `Machine::verifier_key(&program, tier, reduce) -> Arc<CommonData<Config>>`. The witness-tape builder is M5.1's `witness::WitnessTape::build`; the tape for an N-proof aggregate is the same construction iterated (M5.3's program).
- **The verifier-key story (R6, spec §11 closed):** the rVM verifier key is `(FriProfile, Program, Tier)`; the preprocessed cap binds every program word; there is no `hc`-style public value. The fullnode pins **the aggregate program's digest (4 field elements) + the admitted tier set + the production profile**, holds the program as a registered deterministically-rebuildable artifact (`programs::verify_rv32(shape, key, Checkpoints::Off)` and its committed `.digest`), and calls `Machine::verify(&program, proof)`. The declared heights (`reg`, `ram`, `poseidon2`, `reduce`) are proof-carried and range-checked, never key components.
- **The public interface (R5):** every rVM proof's batch public values are exactly 4 field elements — `public_digest(interface_words)` — and the fullnode's admission recomputes the §4.4 list from the covered bundles' public fields and compares the digest (the cs6 `verify_public`/`H_PUB` pattern). `recursion::public_values::{public_digest, interface_words}` are the two shared host functions.
- **The measured exit numbers** (Task 10, recorded in `recursion/docs/01-rvm-machine.md`): the rVM proof's size in bytes at the production exit tier (est. ~0.5–0.6 MB against the fullnode's 2 MiB cap), prove time (est. 20–40 min), verify time cold/warm, key-build time, and the peak resident memory (est. ~55–65 GB, ≥ 64 GB machine) — the economics the chain-side aggregation design (`fullnode/docs/aggregation.md`) is waiting for.
- **The ISA at 26 instructions** (`REDUCE` = 24, `SPONGE` = 25; 0–23 frozen), the emulator extended as reference semantics, and the re-pinned verifier program with its three-stage row measurements — the base on which M5.3 builds the aggregate program (one program per `(shape, N)`), and M5.4 the self-verifier.
