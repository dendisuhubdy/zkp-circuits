# Rand zkVM M4.4 — SHA-256 chip and the sBPF interpreter guest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tenth AIR table proves SHA-256 compressions behind a `SHA256` syscall (`SYS_SHA256 = 5`), and an sBPF interpreter compiled to RV32IM runs a Solana program's ELF as a guest — M4.4's exit test: an SPL Token `Transfer` instruction, with its accounts as private input, proves and verifies under `R_exec`, and M4's exit criterion ("an ERC-20 `transfer` and an SPL `Transfer` each prove") is met.

**Architecture:** The chip repeats M4.2's pattern exactly: one row per round (64 rows per compression, a 64-row block with no idle rows because the final add and the eight write-backs fit on the last round row), proof-declared and optional height (`sha256_log_height`, 0 = absent), chip-owned `MEMORY` traffic (24 reads on row 0, 8 writes on row 63), a two-element `SHA256` lookup bus from the cpu's ecall row, honest zero-state padding blocks. The interpreter repeats M4.3's: a `no_std` `sbpf-core` library generic over a `Host` trait (`sha256_compress` is the only chip-backed operation), unit-tested natively, differentially tested against `solana-sbpf` 0.11.1 on the host, and compiled into a 40-line `guest-sdk` binary. Inputs are the ELF and the serialized instruction (accounts, data, program id); the public output binds the program, the input and the writable accounts' post-state through SHA-256 digests, so the chip is on the exit test's own path.

**Tech Stack:** Rust 1.98.1, Plonky3 0.7 (unchanged), `riscv32im-unknown-none-elf` + `llvm-tools`, `guest-sdk`, `sha2 = "=0.10.9"` (dev, host oracle for the reference), `solana-sbpf = "=0.11.1"` (dev, host oracle for the interpreter), `hex 0.4`. No Solana toolchain: the SPL Token ELF is fetched once from the live program account and committed with its sha256 (Task 6).

**Spec:** `docs/superpowers/specs/2026-09-11-zkvm-m4-design.md` §5 (M4.4, interfaces only), §3 and §3.1 (the chip pattern this plan repeats), §6, §7, §8. Background: `research/docs/04-guests.md` (the Solana path; "M4.3's SHA-256 chip should plan its column budget against [the keccak table's proof-size cost] — and should be optional the same way"), `research/docs/02-tables-and-buses.md` (the keccak section is the template), `docs/superpowers/plans/2026-09-12-zkvm-m4-2.md` (Tasks 3–4: how a chip is wired), `docs/superpowers/plans/2026-09-12-zkvm-m4-3.md` (the `Host`-trait guest pattern; `evm-core`'s `abi.rs` is the template for `sbpf-core`'s).

## Global Constraints

- Every cargo command: `cargo +1.98.1 ...` run from `research/`; guest crates are their own workspace roots.
- **Invariant 1** (`AGENTS.md`): every bus message column is constrained on every row kind that sends it. **Invariant 2**: a bus count is forced to zero wherever the message columns are unconstrained. Padding blocks are honest compressions of the all-zero state and all-zero message with every count zero.
- **Degree cap 8**: the sha256 table's measured max constraint degree is pinned in `tests/tables.rs::alu_max_constraint_degree_is_pinned` (10 entries now; expected 3, any measured value is written down). The cpu table stays at 8 — the new selector adds only degree-≤2 terms, exactly as `SYS_KECCAK`'s did.
- **Chip order**: `Chip::Sha256` appended **last** in `machine::chips()` (after `Keccak`), index 9; `Traces::as_slice`/`heights` become `[_; 10]`; `log_ext_degrees` pushes the sha256 entry after the keccak entry.
- **Bus catalogue**: one new `LookupBus`, `bus::SHA256`, message `[clk, ptr]`. Memory traffic uses the existing `bus::MEMORY` (`[space, addr, ts, value, is_write]`), reads at `ts = 4·clk + 0`, writes at `ts = 4·clk + 1`, as the keccak chip does.
- **ABI** (spec §5): `SYS_SHA256 = 5`, `a0 = ptr`, a **word** address of `SHA256_WORDS = 24` words: words `0..16` = the 512-bit message block as sixteen 32-bit **big-endian-valued** words `W[0..16]` (word `i` holds bytes `4i..4i+4` of the block as `u32::from_be_bytes`), words `16..24` = the state `H[0..8]`; one compression, `H ← H + f(H, W)`, written back in place over words `16..24`; words `0..16` unchanged. No second argument. `ptr ≤ SHA256_PTR_LIMIT = 0x3000_0000 − 24` in the emulator; the AIR bounds `ptr < 2^30` via the same limb decomposition and `RANGE8`/`AND4` lookups `KECCAK_PTR` uses. Padding and the Merkle–Damgård loop live in the guest SDK (`guest_sdk::sha256`), as `keccak256`'s sponge does.
- **Block geometry**: `ROUNDS = 64`, `BLOCK = 64` (no idle rows), `sha256_log_height(n) = if n == 0 { 0 } else { max(6, log2_ceil(64·n)) }`; `Proof.sha256_log_height: u8`; `verify` checks `slh == 0 || 6 ≤ slh ≤ min(tier + 6, MAX_SHA256_LOG_HEIGHT = 20)` (one compression is one cpu cycle, so `2^t` cycles bound the rows at `2^(t+6)`); a cpu row with `SYS_SHA256` in a proof with `slh = 0` is unprovable because its `SHA256` lookup has no provider (the same argument M4.2 Task 6 made for keccak; pinned by a cheating test).
- **Memory height**: a `SYS_SHA256` row makes 32 memory accesses (24 reads + 8 writes) instead of 4; `mem_log_height` is proof-declared since M4.2 and `check_declared_heights`/`build_traces_salted` account `4·cycles + 100·n_keccak + 32·n_sha256`. The verifier-key cache key gains a fifth component: `verifier_key(tier, program_log_height, input_log_height, keccak_log_height, sha256_log_height)`. (The fullnode's `deploy/sync-zkvm.sh` anchors on this signature; its update is the vendoring's job, noted in the docs.)
- **Equality contract**: the chip's write-back on any `(H, W)` equals `sha2`'s `compress256` bit for bit; a randomized test compares 1,000 blocks; `sha256::sha256(msg)` equals `sha2::Sha256::digest(msg)` on the FIPS 180-4 vectors and 1,000 random messages.
- **Interpreter scope** (spec §5): `solana-sbpf` 0.11.1's instruction set — the SBPF **v1** encoding SPL Token's committed ELF uses (the loader's `sbpf_version` for a non-upgradeable BPFLoader2 program), 11 registers × 64 bits, memory regions program `0x1_0000_0000`, stack `0x2_0000_0000` (4 KiB frames, `MAX_CALL_DEPTH = 64`, so 256 KiB is *not* affordable in a 1 MiB guest: this plan allocates 64 frames × 512 bytes = 32 KiB and traps on a frame that would exceed it — SPL Token's `process_transfer` uses well under that; the exact frame depth and high-water mark are measured in Task 6), heap `0x3_0000_0000` (32 KiB, bump allocator via `sol_alloc_free_`), input `0x4_0000_0000`; syscalls `abort`, `sol_panic_`, `sol_log_`, `sol_log_64_`, `sol_log_compute_units_`, `sol_log_pubkey`, `sol_memcpy_`, `sol_memmove_`, `sol_memset_`, `sol_memcmp_`, `sol_alloc_free_`, `sol_sha256` (the chip). `sol_ed25519`/`sol_secp256k1_recover`/`sol_keccak256`/`sol_invoke_signed_*`/`sol_get_*_sysvar`/`sol_create_program_address`/`sol_try_find_program_address` trap (a PDA derivation needs `sol_sha256` with the `"ProgramDerivedAddress"` marker and the curve check; the curve check is Ed25519 work and out of scope, `docs/04-guests.md`).
- **Instruction meter**: `MAX_INSTRUCTIONS = 200_000` (Solana's default compute budget); exceeding it is an exceptional halt. Solana's per-syscall compute costs are **not** modelled (nothing on-chain depends on them yet).
- **Status word** (`out0`): `1` = the program returned `r0 == 0` (success), `0` = the program returned a non-zero `r0` (a `ProgramError`, its low 32 bits in `out1` is **not** available — the digest owns `out1..7` — so the error code is bound only through the output hash's absence: post-state = pre-state), `2` = exceptional halt (access violation, bad instruction, unknown syscall, call-depth or instruction-meter overflow, unsupported ELF). Both `0` and `2` bind `post_accounts_hash = pre_accounts_hash`.
- **Public output** (plan ruling): `out0 = status`, `out1..7` = words `0..6` of `hash(domain::SBPF_OUT = 14, [program_hash(8) ‖ input_hash(8) ‖ output_hash(8)])` with `program_hash = sha256(elf bytes)`, `input_hash = sha256(serialized input as passed to the program)`, `output_hash = sha256(for each account in order: lamports as 8 LE bytes ‖ data_len as 8 LE bytes ‖ data)` over the **post**-state of every account (writable or not) — all three through the chip, so the exit test compresses several thousand blocks and is the chip's real workload. Hash words packed `word[i] = LE(bytes[4i..4i+4])` as M4.3 does.
- **Input vector layout**: `[n_elf, elf bytes…, n_input, input bytes…]`, byte strings 4 per word little-endian, zero-padded. `MAX_ELF_BYTES = 262_144`, `MAX_INPUT_BYTES = 16_384`.
- **Serialized input** (host side, `research/src/sbpf.rs`): the *aligned* format `solana-program`'s entrypoint deserializes (`solana_program::entrypoint::deserialize`): `u64 n_accounts`; per account: `u8 dup` (`0xff` = not a duplicate, else the index of the account it duplicates followed by 7 padding bytes and nothing else), `u8 is_signer`, `u8 is_writable`, `u8 executable`, `[u8; 4]` padding (`original_data_len` slot), `[u8; 32] key`, `[u8; 32] owner`, `u64 lamports`, `u64 data_len`, `data`, `MAX_PERMITTED_DATA_INCREASE = 10_240` bytes of realloc padding, padding to an 8-byte boundary, `u64 rent_epoch`; then `u64 data_len`, instruction data, `[u8; 32] program_id`. `research/src/sbpf.rs` implements it with a test against the byte offsets `solana-sbpf`'s own test harness (or `solana-program`'s deserializer, if the crate builds offline) reports.
- **Tier**: the exit test's `Transfer` must prove at **tier 18 or lower**; the number is M4.4's first result (Task 6 records program words, input words, cycles, sBPF instructions executed, compressions, tier, `sha256_log_height`, `mem_log_height`, proof size). Above tier 16, the report breaks the cycle count down (instruction dispatch, 64-bit ALU emulation, memory translation, the three digests) for the follow-up.
- **Docs carry measured numbers**: sha256 table width, its degree, the SPL Token guest's program words / cycles / tier, the proof-size delta of one sha256 block, and test counts in `README.md`, `AGENTS.md`, `docs/05-roadmap.md`.
- The fullnode is **not** re-vendored by this plan (a constraint-set change: new table, new syscall, `Proof` gains a `u8`, `verifier_key` arity 5).
- Commit style as M4.2/M4.3: `research: sha256 — …`, `research: sbpf — …`, `research: docs — …`.

## Rulings made in this plan

| ruling | why | cost if wrong |
|---|---|---|
| the sha256 chip is optional per proof with a proof-declared height, not `2^(t−1)` as spec §5 sketched | M4.2 measured what a wide table costs every proof (+1.91 MB for keccak); `docs/04-guests.md` already asks for the same optionality; spec §3.1 is the precedent | one more `u8` in `Proof`, one more key component |
| 64-row blocks with no idle rows: 24 reads on row 0, 8 writes on row 63 | SHA-256's final add is a function of row 63's local post-round state and the block-constant `H`, so the writes need no extra rows; a power-of-two block keeps the height arithmetic trivial | 32 memory sends on two rows of one chip; the memory bus is a permutation, sends per row are only a column-count question (measured in Task 3) |
| every row holds its post-round `a'`/`e'` as limbs with carries; the transition pins the next row's bits to them | Plonky3 AIRs see local and next only; `b, c, d` and `f, g, h` are shifted copies of earlier `a`/`e`, so keeping their bits in the row (192 bit columns) is what makes Maj/Ch degree ≤ 3 without a lookup | ~300 columns, well under keccak's 2,612 |
| the exit test's digests go through the chip (`program_hash`, `input_hash`, `output_hash`) | the spec's exit test (an SPL `Transfer`) does not itself call `sol_sha256`; binding the run's identity and effect with SHA-256 puts the chip on the critical path with a real workload (thousands of compressions) and gives the chain Solana-native digests | the ELF's ~1,600 compressions dominate the row count; a follow-up may bind the program by a cached digest instead |
| SBPF v1 semantics, static 32 KiB stack, no compute-unit costs | it is what the committed SPL Token ELF was built for; frames are measured, not assumed | a program needing deeper frames traps; the constant is one line |
| the SPL Token ELF is fetched from the live program account and committed | building it needs the Solana toolchain (`cargo build-sbf`), which the build machines do not have; the on-chain bytes are the canonical artifact and their sha256 is committed with them | network once, at plan execution; `SPL_TOKEN.md` records the RPC command and the slot |
| `solana-sbpf` is the differential oracle | an interpreter with 100+ opcodes and 64-bit-in-32-bit arithmetic is where bugs hide; the reference implementation is a crate away | one dev-dependency, host only |
| status `0` carries no error code | eight output words are spoken for; the error is recoverable off-chain by re-running, and on-chain by "the post-state equals the pre-state" | a chain that wants the code re-cuts `out1..7` |

fn sys_sha256_compresses_the_24_words_in_place_in_one_cycle() {
    use rand_zkvm::{asm::{ops, Assembler}, emulator::run, sha256};
    let base = 0x100u32;                       // word address of the 24-word buffer
    let block: [u32; 16] = core::array::from_fn(|i| 0x0101_0101u32.wrapping_mul(i as u32 + 1));
    let mut a = Assembler::new();
    for (i, w) in block.iter().enumerate() { a.extend(ops::store_word_imm(base + i as u32, *w)); }
    for (i, h) in sha256::IV.iter().enumerate() { a.extend(ops::store_word_imm(base + 16 + i as u32, *h)); }
    a.extend(ops::call_sha256(base));
    for i in 0..8 { a.extend(ops::load_word(base + 16 + i, 10 + i)); a.extend(ops::write_output(i, 10 + i)); }
    a.extend(ops::halt());
    let p = a.program();
    let exec = run(&p, &[], 4096).unwrap();
    let mut want = sha256::IV; sha256::compress(&mut want, &block);
    assert_eq!(exec.outputs, want);
    let rows: Vec<_> = exec.events.iter().filter_map(|e| e.sha256_row.clone()).collect();

    assert_eq!(rows[0].ptr, base); assert_eq!(rows[0].block, block); assert_eq!(rows[0].h_in, sha256::IV); assert_eq!(rows[0].h_out, want);
    // the row's memory accesses: 24 reads at ts 4clk, 8 writes at ts 4clk+1, message words unchanged
    let ev = exec.events.iter().find(|e| e.sha256_row.is_some()).unwrap();
    assert_eq!(ev.sha256_accesses.iter().filter(|a| !a.is_write).count(), 24);
    assert_eq!(ev.sha256_accesses.iter().filter(|a| a.is_write).count(), 8);
    assert!(exec.events.iter().filter(|e| e.sha256_row.is_some()).count() == 1);
}

- [ ] **Step 3: Implement the table**

Layout per row (`col`): `IS_REAL`, `CLK`, `PTR` (block-constant; `PTR` limbs for the `< 2^30` bound are on the *cpu* side, the chip trusts the lookup), `A_BITS[32]`, `B_BITS[32]`, `C_BITS[32]`, `E_BITS[32]`, `F_BITS[32]`, `G_BITS[32]`, `D_LO, D_HI`, `H_LO, H_HI` (16-bit limbs), `W[16]` as `(lo, hi)` limb pairs (32 columns; a ring: on row `t`, slot `t % 16` holds `W[t]`), `WM2_BITS[32]`, `WM15_BITS[32]` (bits of `W[t−2]` and `W[t−15]`, pinned to the ring's limbs; zero on rows `t < 16` where they are unused), `WNEW_LO, WNEW_HI, WNEW_CARRY` (the `W[t]` the schedule computes for `t ≥ 16`; on rows `t < 16` `WNEW` equals the memory read), `T1_LO, T1_HI, T1_CARRY` (`T1 mod 2^32` and its carry ≤ 4, as 3 bits), `A_NEW_LO, A_NEW_HI, A_CARRY` (`T1 + T2`), `E_NEW_LO, E_NEW_HI, E_CARRY` (`d + T1`), `HIN[8]` as limb pairs (16, block-constant), `HOUT[8]` as limb pairs + 8 carry bits (used on `IS_LAST`), plus the memory-send auxiliary columns the `MEMORY` permutation needs (as `tables/keccak.rs` allocates them: one set per send, 24 + 8 = 32 sends but only 24 live on row 0 and 8 on row 63 — allocate 24 send slots and reuse 8 of them on the last row, gated by `IS_FIRST`/`IS_LAST`). Preprocessed (`pre`): `IS_FIRST`, `IS_LAST`, `K` (the round constant), `T_LT_16`, `ROUND_IDX` (0..63, for the ring slot selectors — or 16 one-hot slot flags `SLOT[i]`, which keeps the ring rules degree 2; use the one-hot).

Rules (all gated so they hold on padding too):
1. Bits are booleans; every limb is range-checked through the existing `RANGE16`/`RANGE8` lookups the memory and keccak tables use.
2. **Schedule** (`t ≥ 16`, i.e. `1 − T_LT_16`): `WNEW = σ1(WM2) + W[t−7] + σ0(WM15) + W[t−16]` with `σ` as linear combinations of the bit columns and the sum equated to `WNEW_LO + 2^16·WNEW_HI + 2^32·WNEW_CARRY`, carry ≤ 3 (2 bits). `WM2_BITS` compose to the ring slot `(t−2) % 16`, `WM15_BITS` to slot `(t−15) % 16` (selected by the one-hot). On `t < 16`: `WNEW` equals the row's memory read value (rule 6).
3. **Round**: `T1 = h + Σ1(e) + Ch(e,f,g) + K + WNEW` with `Ch = e·f + (1−e)·g` per bit and `Σ1` linear in `E_BITS`; `T2 = Σ0(a) + Maj(a,b,c)`, `Maj = ab + bc + ca − 2abc` per bit; `A_NEW = T1 + T2 mod 2^32`, `E_NEW = d + T1 mod 2^32`, each with its carry columns.
4. **Transition** (`1 − IS_LAST`): `next.A_BITS` compose to `A_NEW`; `next.B_BITS = A_BITS`; `next.C_BITS = B_BITS`; `next.D = compose(C_BITS)`; `next.E_BITS` compose to `E_NEW`; `next.F_BITS = E_BITS`; `next.G_BITS = F_BITS`; `next.H = compose(G_BITS)`; the ring: `next.W[slot] = W[slot]` for every slot except `(t+1) % 16`, which becomes `next.WNEW`… (simpler: the ring slot `t % 16` is overwritten with `WNEW` on row `t` itself: `W[t % 16] = WNEW` on every row, and all 16 slots carry to the next row unchanged: `next.W[i] = W[i]`; then `W[t−2]` is slot `(t−2) % 16` on row `t`, still valid because slot `t % 16` was last written 16 rows ago — correct). `HIN` carries unchanged. `IS_REAL`, `CLK`, `PTR` carry unchanged.
5. **First row** (`IS_FIRST`): `A..H` compose to `HIN[0..8]` (`a = H0, b = H1, c = H2, d = H3, e = H4, f = H5, g = H6, h = H7`).
6. **Memory**: on `IS_FIRST`, 24 reads `(space = RAM, addr = PTR + i, ts = 4·CLK, value, is_write = 0)` for `i = 0..24` with `value = W[i]` for `i < 16` — but the ring only has slot 0 written on row 0… so the 16 message reads cannot all be checked on row 0 against ring slots. Resolve: read `W[t]` on **row `t`** for `t < 16` (one read per row, `ts = 4·CLK`, `value = WNEW`, gated by `T_LT_16`), and the 8 `HIN` reads on row 0 (`addr = PTR + 16 + i`, `value = HIN[i]`). The memory table orders accesses by `(key, ts)`; 24 reads sharing one `ts` at distinct addresses is what the keccak chip already does over 13 rows, so equal timestamps across rows are fine. On `IS_LAST`: 8 writes `(PTR + 16 + i, ts = 4·CLK + 1, HOUT[i], is_write = 1)`. Counts: `IS_REAL` on every send, zero otherwise (Invariant 2).
7. **Final add** (`IS_LAST`): `HOUT[i] = HIN[i] + state'_i mod 2^32` where `state' = (A_NEW, a, b, c, E_NEW, e, f, g)` — the post-round-63 working variables — with the 8 carry bits.
8. **Bus**: `SHA256` provide `[CLK, PTR]` with count `IS_REAL · IS_FIRST`.
9. **Padding**: `IS_REAL = 0`, `HIN = 0`, `W = 0` (the trace builder runs the honest compression of zeros so every arithmetic rule holds); sends count 0.

Trace builder: per event, 64 rows from `sha256::round` applied step by step (`schedule` for the `W`s), then padding blocks. Record `col::WIDTH` and `pre::WIDTH`; measure the max degree with the existing helper used for the keccak pin.

/// M4.4 exit test: an SPL Token Transfer instruction proves and verifies; the public output binds the program, the input and the post-state accounts through SHA-256.
#[test]
fn compiled_sbpf_spl_token_transfer_proves_and_verifies() {
    use rand_zkvm::sbpf::{deserialize_accounts, spl_transfer};
    let m = Machine::new(FriProfile::Test);
    let p = guests::compiled::sbpf();
    let call = spl_transfer(250);
    let inputs = call.input_words();
    let (want, r0, post) = call.expected();
    assert_eq!(r0, Ok(0)); assert_eq!(want[0], 1);
    let pre = deserialize_accounts(&call.input);
    assert_eq!(u64::from_le_bytes(pre[0].data[64..72].try_into().unwrap()) - 250, u64::from_le_bytes(post[0].data[64..72].try_into().unwrap()));
    assert_eq!(u64::from_le_bytes(pre[1].data[64..72].try_into().unwrap()) + 250, u64::from_le_bytes(post[1].data[64..72].try_into().unwrap()));
    let exec = run(&p, &inputs, Tier(18).max_cycles()).unwrap();
    assert_eq!(exec.outputs, want);
    let (proof, _) = m.prove_salted(&p, &inputs, [13, 14, 15, 16], None).unwrap();
    eprintln!("sbpf spl transfer: {} program words, {} input words, {} cycles, {} sha256 compressions, tier {}, sha256_log_height {}, mem_log_height {}, proof {} bytes",
        p.words.len(), inputs.len(), exec.cycles(), exec.events.iter().filter(|e| e.sha256_row.is_some()).count(), proof.tier.0, proof.sha256_log_height, proof.mem_log_height, proof.to_bytes().len());
    m.verify(&p.digest(), &proof).unwrap();
    assert!(proof.tier.0 <= 18, "M4.4 requires tier ≤ 18");
    assert!(proof.sha256_log_height >= 6);
}
