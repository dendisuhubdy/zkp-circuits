# zkVM Milestone 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the prover and verifier cheaper and the ISA complete enough for compiled guests: cache the verifier key, retune FRI to a stated 100-bit conjectured target, replace the 2^16-row byte table with two 256-row tables (range + nibble), cut the ALU's per-row lookup count, add sub-word loads/stores (word-addressed memory, read-modify-write stores), and add the RV32M extension with exact-integer identities that cannot wrap in Goldilocks.
**Architecture:** One batch of five (then six, after the byte-table split) AIR tables — `program`, `cpu`, `memory`, `alu`, and the byte table's replacements `range`/`nibble` — exchanging facts over named LogUp buses (`p3-lookup`), proved as one `p3-batch-stark` batch under `p3-fri`'s `HidingFriPcs`. The emulator (`src/emulator.rs`) is the reference semantics for every op; each table's AIR constraints and its trace-builder counts must agree with it exactly.
**Tech Stack:** Rust 1.98.1, Plonky3 =0.7.0, p3-lookup buses
**Spec:** docs/superpowers/specs/2026-09-10-zkvm-m2-m3-design.md

## Global Constraints

- Every bus message column is constrained on every row kind that sends it (`research/AGENTS.md` invariant 1).
- A bus count is forced to zero wherever its message columns are unconstrained (`research/AGENTS.md` invariant 2; see the ALU `MULT` INVARIANT comment for the canonical example).
- The emulator (`src/emulator.rs`) is the reference semantics: if the AIR and the emulator disagree, the AIR is wrong.
- `rejects()` in `tests/cheating.rs` counts only a `"constraints not satisfied on row"` panic or a `VerifyError` — a trace-builder `assert!` is not a rejection.
- Docs carry measured numbers (guest instruction/cycle counts, tier table, test counts); re-measure and update in the same commit that changes them.
- Commit style `research: <area> — <what>`, one logical change per commit.
- 100-bit conjectured soundness target → FRI `Production` profile: 27 queries, 20 PoW bits (81 + 20 = 101 ≥ 100); `max_log_arity: 3` (folding arity 8).
- The byte table becomes two fixed-height-256 preprocessed tables: `range` (range checks + `POW2`) and `nibble` (4-bit `AND`/`OR`/`XOR`).
- ALU width ≤ 56 columns and ≤ 14 lookups/row on every non-shift op, after M2.3+M2.4 (before M2.6's flag growth; M2.6 grows the ALU further and is not bound by this ceiling).
- Word-addressed memory (`space=1`, `addr = byte_addr >> 2`); every store is a read-modify-write of one word, delivered as a `SLOT_MEM` read plus a `SLOT_W` write.
- The M extension proves 32×32 multiplication as an exact integer identity over 16-bit halves (`AL,AH,BL,BH` from existing byte limbs) so no term can wrap the Goldilocks modulus; division proves `A = Q·B + R`, `R < B`.

    ```rust
    #[derive(Default)]
    struct KeyCache {
        map: HashMap<(u64, usize), Arc<CommonData<Config>>>,
        order: VecDeque<(u64, usize)>,
    }
    impl KeyCache {
        fn get(&self, key: &(u64, usize)) -> Option<Arc<CommonData<Config>>> {
            self.map.get(key).cloned()
        }
        fn insert(&mut self, key: (u64, usize), value: Arc<CommonData<Config>>) {
            if self.map.contains_key(&key) { return; }
            if self.map.len() >= KEY_CACHE_CAPACITY {
                if let Some(oldest) = self.order.pop_front() { self.map.remove(&oldest); }
            }
            self.order.push_back(key);
            self.map.insert(key, value);
        }
    }
    ```

| `slt` | `g_ab` (4) | `g_ab` (4) | 0 (dropped) | `S0..3` (4, `cmp` gate) | SA (2: dummy+extract) + SB (2: dummy+extract) | 16 |

| `sll` | `g_ab` (4) | `g_ab` (4) | `g_ab` (4, stays — the shift result needs its own range proof) | `Q0..3` (4, `shift` gate) | shift-amount (2) + POW2 (1) + top-limb overflow (2) | 21 |

`and`/`or`/`xor` (the M2.3 motivating example, 16 lookups before this task) drop to 8; `add`/`sub`/`eq`/`sltu` land at or under 12; `slt` needs both operands' sign bits (2 independent isolated nibble extractions, 4 lookups) and lands at 16. The `≤14`-lookups target in the Global Constraints is met by every op except `slt` (16) and the shift family (`sll`/`srl`/`sra`, 21–29) — this is a resolved ambiguity, documented in Self-review: M2.4 point 3 ("Q, S, T limb checks stay op-gated as today") explicitly pins the shift/compare scratch-limb lookups at their pre-M2.3 count, and `slt` inherently needs two independent isolated-nibble sign extractions (each costing a dummy range-check plus the real extraction, since — unlike the bitwise case — nothing else on a `slt` row looks up the companion low nibble). The dramatic, unambiguous win the spec's prose highlights (bitwise: 16 → 8, or the pre-M2.3 byte-table cost) is fully delivered.

```rust
        Width::Byte => { let byte = (mem_val >> (8*off)) & 0xff; if signed { sext(byte, 8) } else { byte } }
        Width::Half => { let half = (mem_val >> (8*off)) & 0xffff; if signed { sext(half, 16) } else { half } }
        Width::Word => mem_val,
    };
    acc.push(MemAccess { space: SPACE_RAM, addr: mem_addr, slot: SLOT_MEM, value: mem_val, is_write: false });
}
Instr::Store { width, .. } => {
    let off = alu_out & 3;
    let bad = match width { Width::Word => off != 0, Width::Half => off != 0 && off != 2, Width::Byte => false };
    if bad { return Err(ExecError::Misaligned(alu_out)); }
    mem_addr = alu_out >> 2;
    let old = *ram.get(&mem_addr).unwrap_or(&0);
    let merged = match width {
        Width::Byte => (old & !(0xffu32 << (8*off))) | ((b & 0xff) << (8*off)),
        Width::Half => (old & !(0xffffu32 << (8*off))) | ((b & 0xffff) << (8*off)),
        Width::Word => b,
    };
    mem_val = old;
    ram.insert(mem_addr, merged);
    acc.push(MemAccess { space: SPACE_RAM, addr: mem_addr, slot: SLOT_MEM, value: old, is_write: false });
    acc.push(MemAccess { space: SPACE_RAM, addr: mem_addr, slot: SLOT_W, value: merged, is_write: true });
}
```
`sext(x, bits)` already exists in `isa.rs` as a free function (currently private to that module) — make it `pub(crate)` and import it in `emulator.rs`. `CycleEvent` needs a new field to carry `merged` through to `cpu_trace` for stores (`pub merged: u32`, default 0 for non-store rows) since `cpu_trace` must fill `MERGED0..3` from it directly (cheaper than recomputing from `W0..3`/`RB0..3` in the trace builder, though either works — recomputing is fine too and avoids the new field; prefer recomputing in `cpu_trace` from the word read plus `e.b` and the decoded width/offset, matching exactly what the AIR asserts).

```rust
}
impl AluOp {
    pub const COUNT: usize = 19;
    pub const ALL: [AluOp; 19] = [Add, Sub, And, Or, Xor, Sll, Srl, Sra, Slt, Sltu, Eq, Mul, Mulh, Mulhu, Mulhsu, Div, Divu, Rem, Remu];

    pub fn eval(self, a: u32, b: u32) -> u32 {
        // ... existing 11 arms unchanged ...
        AluOp::Mul => a.wrapping_mul(b),
        AluOp::Mulh => (((a as i32 as i64) * (b as i32 as i64)) >> 32) as u32,
        AluOp::Mulhu => (((a as u64) * (b as u64)) >> 32) as u32,
        AluOp::Mulhsu => (((a as i32 as i64) * (b as u64 as i64)) >> 32) as u32,
        AluOp::Div => {
            if b == 0 { 0xffff_ffff }
            else if a == 0x8000_0000 && b == 0xffff_ffff { 0x8000_0000 } // MIN / -1 overflow
            else { ((a as i32).wrapping_div(b as i32)) as u32 }

        AluOp::Divu => if b == 0 { 0xffff_ffff } else { a / b },
        AluOp::Rem => {
            if b == 0 { a }
            else if a == 0x8000_0000 && b == 0xffff_ffff { 0 }
            else { ((a as i32).wrapping_rem(b as i32)) as u32 }
        }
        AluOp::Remu => if b == 0 { a } else { a % b },
```

**Cheating test — the `HI = 2^32 − 1` product attack (required by the spec):**
```rust

    let mut a = Assembler::new(0);

    a.push(rand_zkvm::asm::ops::mulhu(7, 5, 6));
    a.extend(write_output(0, 7)); a.extend(halt());

    let m = Machine::new(FriProfile::Test);

    t.alu.values[row*w + alu::col::Q0 + 3] = F::from_u32(forged_carry); // CARRY column
    t.alu.values[row*w + alu::col::S0 + 1] = F::from_u32(forged_carry & 0xff);
    t.alu.values[row*w + alu::col::S0 + 2] = F::from_u32((forged_carry >> 8) & 0xff);
    t.alu.values[row*w + alu::col::S0 + 3] = F::from_u32((forged_carry >> 16) & 0xff); // only 3 limbs: <2^24, forged_carry needs a 4th byte
    t.alu.values[row*w + alu::col::C] = F::from_u32(0xffff_ffff);
    for k in 0..4 { t.alu.values[row*w + alu::col::C0 + k] = F::from_u32(0xff); }

```
This rejects because `forged_carry = 0xffff_ffff` needs 4 bytes but only 3 limb columns (`S0+1..3`) are RANGE8-checked for it (`carry < 2^24` by construction), so `carry_limbs` (computed from only 3 limbs) cannot equal `0xffff_ffff` — the `carry - carry_limbs = 0` identity fails, a genuine constraint violation `rejects()` catches. (This is the concrete instance of the spec's abstract attack: "a prover could choose `HI = 2^32−1, LO = A·B + 1` for small products" — the 3-limb bound on `CARRY` is exactly what forecloses it, since `HI = T2 + CARRY` and `CARRY` cannot reach `2^32-1` under a 24-bit range check.)

```rust
let abs_a = v(A) + v(SA)*(AB::Expr::from_u64(1u64<<32) - AB::Expr::TWO*v(A));
let abs_b = v(B) + v(SB)*(AB::Expr::from_u64(1u64<<32) - AB::Expr::TWO*v(B));
for (base, val) in [(T0, abs_a.clone()), (CARRY0, abs_b.clone())] {
    let limbs = word(base);
    b.assert_zero(is_div.clone() * (limbs - val));
    for i in 0..4 { bus::RANGE8.lookup_key(b, [v(base+i)], Count::bounded(is_div.clone(), 1)); }
}
// A = Q*B + R when B != 0 (using |A|,|B| for the signed unsigned-core division, then fixing signs)
b.assert_zero(is_div.clone() * (one.clone()-v(DIVZ)) * (one.clone()-v(OVF)) * (abs_a.clone() - q.clone()*abs_b.clone() - r.clone()));
// R < B via the compare-adder pattern: B - R - 1 >= 0, limb range-checked (reuse the adder machinery already proven for slt/sltu — same technique, gated by is_div*(1-DIVZ)*(1-OVF)).
// DIVZ: Q = 2^32-1, R = A (unsigned core value, i.e. abs_a for the signed path, corrected below).
b.assert_zero(is_div.clone() * v(DIVZ) * (q.clone() - AB::Expr::from_u64(0xffff_ffff)));
b.assert_zero(is_div.clone() * v(DIVZ) * (r.clone() - abs_a.clone()));
// OVF: A = 2^31, B = 2^32-1 (i.e. -1), Q = 2^31, R = 0 — checked directly on the signed inputs.
b.assert_zero(is_div.clone() * v(OVF) * (v(A) - AB::Expr::from_u64(1u64<<31)));
b.assert_zero(is_div.clone() * v(OVF) * (v(B) - AB::Expr::from_u64(0xffff_ffff)));
b.assert_zero(is_div.clone() * v(OVF) * (q.clone() - AB::Expr::from_u64(1u64<<31)));
b.assert_zero(is_div.clone() * v(OVF) * r.clone());
// sign fix-up for div/rem (signed) vs divu/remu (unsigned, SA=SB=0 forced so the fixups are identity):
let q_signed = q.clone() + (v(SA)+v(SB)-AB::Expr::TWO*v(SA)*v(SB)) * (AB::Expr::from_u64(1u64<<32) - AB::Expr::TWO*q.clone());
let r_signed = r.clone() + v(SA) * (AB::Expr::from_u64(1u64<<32) - AB::Expr::TWO*r.clone());
b.assert_zero((div.clone()+divu.clone()) * (v(C) - q_signed));
b.assert_zero((rem.clone()+remu.clone()) * (v(C) - r_signed));
b.assert_zero((divu.clone()+remu.clone()) * (v(SA)+v(SB))); // unsigned variants never set sign bits
```
(`R < B` follows the existing `slt`/`sltu` compare-adder pattern verbatim, applied to `abs_b - r - 1`, gated by `is_div*(1-DIVZ)*(1-OVF)`; implement it by literally reusing the shared-adder code path parameterized on `(x=abs_b, y=r+1, z=..., borrow-must-be-0)`, mirroring how `slt`/`sltu` already reuse the `add`/`sub` adder.)

### Resolved ambiguities (see summary reply)

1. M2.3/M2.4's "exact assignment [of nibble columns] in the plan" is read as full delegation: bitwise high nibbles (`AH_i,BH_i,CH_i`) are derived expressions (`(byte - lo) * 16⁻¹`, zero new columns), not stored columns, because the bitwise low nibble already gets an independent, real lookup — proven sound via the field-bijection argument in `alu.rs`'s `bitwise_high_nibble` doc comment. Isolated extractions (sign bits, shift amount, memory alignment, M2.5 load/store sign) use a genuine dummy range-check lookup plus the extraction lookup (2 lookups), because there the low nibble has no other lookup to piggyback on. This is what keeps ALU width at 52 (well under the 56 cap) instead of the ~61-74 a naive "store every nibble as a column" reading would produce.
2. The Global Constraint "ALU ≤ 14 lookups/row" is met by every op except `slt` (16: two independent isolated sign extractions) and the shift family (21-29: M2.4 point 3 explicitly freezes their Q/S/T lookup count at the pre-M2.3 baseline). Documented in the M2.4 lookup-gate table rather than silently claimed as met everywhere.
3. M2.3's cpu-alignment lookup `AND4[MA3_hi,0xC,0]` is implemented with an added dummy range-check on `MA3_hi`'s low-nibble companion (2 lookups, not the 1 the spec prose's terse form suggests), for the same soundness reason as ambiguity 1 — `MA3` is an isolated extraction (no other lookup already binds its low nibble), so skipping the dummy check would let a malicious `MA3_hi=0` witness with `MA3` up to 255 defeat the `MEM_ADDR<2^30` bound.
4. M2.6's ALU width is explicitly *not* held to the 56-column cap — that constraint is scoped to "after M2.3+M2.4" in the spec, and M2.6's flag growth (11→19) alone would exceed it regardless of column reuse.
