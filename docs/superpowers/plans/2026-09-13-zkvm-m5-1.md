# Rand zkVM M5.1 — the recursion VM's ISA, emulator, DSL and verifier program Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new `recursion/` crate holds the recursion VM's 24-instruction field-native ISA, its emulator, the DSL programs are written against, and a DSL program that verifies a real RV32-machine proof — and reports, from the emulator, exactly how many cpu rows and Poseidon2 permutations one inner 80-query bundle proof costs. M5.1's exit: 50 real production-profile bundle proofs accepted, 50 tampered ones refused at the same step as `rand_zkvm::machine::verify`, and the measured count written down so M5.2's tier table and the `FRIFOLD`/`EXPBITS` question are decided by a number rather than an estimate. No AIRs, no prover — those are M5.2.

**Architecture:** The rVM is a second machine whose word is a Goldilocks element (spec §2). This milestone builds only its *semantics* and its *first program*. `isa.rs` fixes the encoding (one instruction = four field elements) and the program digest (Poseidon2 over the encoded words, one permutation per instruction, `rand_zkvm::hash::permute_state` as the reference permutation, so M5.2's `program` table and the RV32 machine's `hc` mechanism are the same construction). `emulator.rs` is the reference semantics — the AGENTS.md rule that "if the AIR and the emulator disagree, the AIR is wrong" transfers verbatim — and it is also the measuring instrument: it logs one event per instruction with the memory accesses and the permutation the row dispatches, so cpu rows and permutations per inner proof are a byproduct of running the program, not an estimate. `dsl/` is a Rust builder with typed handles and a linear register allocator that spills to memory; on top of it sit a duplex challenger, a padding-free leaf sponge, a truncated-permutation compressor and a Merkle-path walk, each differentially tested against the very `p3-challenger`/`p3-symmetric`/`p3-merkle-tree` code the native verifier calls. `programs/rv32.rs` is then a port of `verify_batch` → `HidingFriPcs::verify` → `verify_fri` → `verify_multi_batch`, step for step, in the order those functions run, with the per-instance constraint evaluation generated at build time by walking each RV32 AIR with Plonky3's symbolic builder. Every phase has a differential test against a host-side replay of the same transcript, and every assertion in the program is a named checkpoint, so "refused at the same step" is a checked claim and not a hope.

**Tech Stack:** Rust 1.98.1, Plonky3 0.7 (`p3-goldilocks`, `p3-field`, `p3-symmetric`, `p3-challenger`, `p3-poseidon2`, `p3-air`, `p3-batch-stark`, `p3-lookup`, `p3-fri`, `p3-merkle-tree`, `p3-commit`, `p3-uni-stark`, `p3-matrix`, `p3-util` — all `=0.7.0`, exactly as `research/Cargo.toml` pins them), `rand_zkvm` itself as a path dependency (the reference permutation, `Proof`, `Machine::verifier_key`, `chips`, the `Chip` AIRs, the bundle guest and the ledger fixtures), `rand 0.10`, `serde`/`postcard` (only to read a `Proof`; the rVM serialises nothing in M5.1), `hex` (dev). No new external crates, no CUDA, no RISC-V target — nothing in this crate ever cross-compiles.

**Spec:** `docs/superpowers/specs/2026-09-13-zkvm-m5-recursion-vm-design.md` §2 (the crate layout), §3 (the ISA and encoding, verbatim below), §4.1–§4.4 (the DSL, the verifier program, generated constraint evaluation, public values), §7 (M5.1's exit test and the measurement decision point), §8 (testing), §10 (the rulings this plan inherits). Background: `.superpowers/spike/report.md` in the `spike-recursive-verifier` worktree (the measured phase breakdown, the exact permutation split — 31 314 leaf sponge / 11 262 path compression / 986 challenger per inner proof — and the throwaway RV32 port whose ordering this plan follows), `research/AGENTS.md` (invariants, testing and docs discipline, commit style), `docs/superpowers/plans/2026-09-12-zkvm-m4-4.md` (the format this plan follows), `research/docs/02-tables-and-buses.md` (the table/bus conventions M5.2 will mirror).

### The instruction set (spec §3, verbatim)

Every instruction is one cpu row. Operands are register indices (`r0..r31`; `r0` is the constant zero) or an immediate field element. `E` denotes an extension operand: the pair `(r, r+1)`.

| mnemonic | operands | effect |
|---|---|---|
| `FADD FSUB FMUL` | `rd, ra, rb` | base-field arithmetic |
| `FADDI FMULI` | `rd, ra, imm` | base-field arithmetic with an immediate |
| `EADD ESUB EMUL` | `Ed, Ea, Eb` | extension-field arithmetic (two rows' worth of work in one row: 2 adds, or 3 muls + 2 adds) |
| `EMULF` | `Ed, Ea, rb` | extension × base |
| `INV` | `rd, ra` | `rd = ra⁻¹` supplied by the prover as a hint; the row constrains `ra·rd = 1` (and `ra ≠ 0`) |
| `EINV` | `Ed, Ea` | extension inverse, same hint-and-check shape |
| `MOV` | `rd, ra` | copy |
| `LOAD STORE` | `rd/rs, ra, imm` | memory cell at `ra + imm` |
| `LOADE STOREE` | `Ed/Es, ra, imm` | two consecutive cells |
| `JMP` | `imm` | `pc = imm` |
| `JEQ JNE` | `ra, rb, imm` | branch on base-field equality |
| `HINT` | `rd` | `rd = next witness word` |
| `HINTE` | `Ed` | two witness words |
| `PUBLIC` | `ra` | append `ra` to the public values |
| `POSEIDON2` | `ra` | permute the eight cells at `ra..ra+8` in place (one row; the work is in the `poseidon2` chip) |
| `HALT` | — | end |

Twenty-four instructions. **Deliberately absent: `FRIFOLD`, `EXPBITS`, `MERKLE` precompiles** — the verifier's FRI fold step and Merkle path step are compiled sequences of the above, and Task 7 adds the first two *only if* Task 6's measurement puts one inner proof above 2^19 cpu rows.

- **Encoding:** one instruction = 4 field elements `[opcode | rd | ra | rb-or-imm]`. Opcode numbering is the table's reading order, fixed by `Op as u8` (0 = `FADD` … 23 = `HALT`) and pinned by a test; changing it changes every program digest.
- **Field types:** `F = Goldilocks` (`rand_zkvm::machine::Val`), `EF = BinomialExtensionField<F, 2>` (`rand_zkvm::machine::Challenge`), an extension element stored as `(c0, c1)` with value `c0 + c1·X`, in two consecutive registers or cells.
- **Memory:** a flat array of cells addressed by a field element; every address used by `LOAD`/`STORE`/`LOADE`/`STOREE`/`POSEIDON2` must satisfy `addr < MEM_LIMIT = 2^24` (and `addr + 7 < 2^24` for `POSEIDON2`, `addr + 1 < 2^24` for the extension forms). `pc < 2^24` likewise. Violations are emulator errors in M5.1 and range-check failures in M5.2.
- **No salted input commitment** (spec §2, §10): the rVM reads its witness with `HINT` in consumption order and commits to nothing about it. Its public values are its entire interface. The RV32 machine's own `H_IN` salting is untouched and its unsalted-public-input segment (M4.4 spec §5.1 item 8) is out of scope.
- **Program binding:** `Program::digest() -> [F; 4]` is a padding-free-sponge-shaped Poseidon2 fold over the encoded words with the header in the *capacity* lanes, exactly mirroring `rand_zkvm::hash::program_digest`'s construction (`research/src/hash.rs:119`): `state = [0, 0, 0, 0, RVM_PROGRAM_DOMAIN, n_instructions, 0, 0]`, then one permutation per instruction absorbing its four encoded words into rate lanes `0..4`, digest = `state[..4]`. One permutation per instruction exactly, which is the number M5.2's `program` table is sized against. `RVM_PROGRAM_DOMAIN = 15`: `rand_zkvm::notes::domain` is occupied through 14 (`SBPF_OUT`), and this must not collide since both hash domains share one permutation.

### The proof system being verified — facts that bind the port

Read off `research/src/machine.rs`'s `Config` and the vendored Plonky3 0.7 sources; each one would silently break the port if guessed.

- `Val = Goldilocks`, `Challenge = BinomialExtensionField<Val, 2>`, `Perm = Poseidon2Goldilocks<8>`, `Hash = PaddingFreeSponge<Perm, 8, 4, 4>`, `Compress = TruncatedPermutation<Perm, 2, 4, 8>`, `ValMmcs = MerkleTreeHidingMmcs<Packing, Packing, Hash, Compress, StdRng, 2, 4, 4>`, `Challenger = DuplexChallenger<Val, Perm, 8, 4>`, `Pcs = HidingFriPcs<..>`, `cap_height = 2`, `FriParameters { log_blowup: 3, log_final_poly_len: 0, max_log_arity: 3, num_queries, commit_proof_of_work_bits: 0, query_proof_of_work_bits, .. }`, `num_random_codewords = 4` (`research/src/machine.rs:15-26, 96-116`).
- **A digest is 4 field elements, not 8.** `DIGEST_ELEMS = 4` in the `ValMmcs` type, `OUT = 4` in the sponge, `CHUNK = 4` in the compressor. Spec §4.1's `Digest ([Felt; 8])` and §4.4's "inner verifier key digest (8 elements)" are written for an 8-lane digest this machine does not have; see the rulings table. The permutation *state* is 8 wide; a digest is its first four lanes.
- **A commitment is a `MerkleCap` of 4 digests** (`cap_height = 2`, `N = 2`), i.e. 16 field elements, and a Merkle walk ends two levels below the root: `verify_batch` compares `commit[cap_index] == digest` with `cap_index` the index left after the walk (`p3-merkle-tree-0.7.0/src/mmcs/batch.rs:267`).
- **Every committed leaf row carries 4 salt elements**, appended after the row's real values, and the widened dimensions are what the inner tree sees: `MerkleTreeHidingMmcs::verify_multi_batch` re-attaches `salts[q][m]` and widens each `Dimensions.width` by `SALT_ELEMS = 4` (`p3-merkle-tree-0.7.0/src/hiding_mmcs.rs:232-275`).
- **Every committed matrix except the preprocessed one is 4 columns wider than its trace**, and each opened point's values are split into a public prefix and a 4-element hidden suffix that the hiding wrapper re-appends before the inner verify: `HidingFriPcs::commit` sets `width = mat_width + num_random_codewords` (`p3-fri-0.7.0/src/hiding_pcs.rs:110-135`), `commit_preprocessing` does **not** widen (only doubles the height), and `HidingFriPcs::verify` extends each `point.1` by the round's random openings before delegating (`hiding_pcs.rs:365-441`). So the program reads, per round/matrix/point, `width` public values *and* 4 hidden values, and hashes their concatenation plus 4 salts.
- **`is_zk() == true`**, so per instance `base_degree_bits = degree_bits[i] - 1`, the committed quotient-chunk count is `(1 << log_num_quotient_chunks[i]) << 1`, and there is a `random` round and a `random` opened value of `DIMENSION = 2` per instance (`p3-batch-stark-0.7.0/src/verifier/mod.rs:404-418`).
- **The transcript order** (`p3-batch-stark-0.7.0/src/verifier/mod.rs:459, 565, 569-570, 580-591, 606`, bodies in `src/transcript.rs`):
  1. `observe_instance_count(n)` — one `observe_usize`;
  2. per instance, `observe_instance_binding(ext_db, base_db, width, n_chunks)` — four `observe_usize`;
  3. `observe_main(&commitments.main, public_values)` — the main cap (16 elements), then every instance's public values in order;
  4. `observe_preprocessed(&preprocessed_widths, preprocessed)` — one `observe_usize` per instance, then the preprocessed cap;
  5. `sample_perm_challenges` — exactly two extension draws, `alpha_lookup` then `beta` (everything else it computes is arithmetic on that pair);
  6. `observe_perm_and_sample_alpha` — the permutation cap, then each present `lookup_terminals[i].0` as an extension element, then one extension draw: `alpha`;
  7. `observe_quotient_commitment` (cap), `observe_random_commitment` (cap);
  8. `sample_zeta` — one extension draw.
  `observe_usize(v)` is `observe_base_as_algebra_element::<Challenge>(Val::from_usize(v))` = `observe_slice(&[v, 0])`: **two** base absorbs per metadata word (`transcript.rs`'s `observe_usize`, `p3-challenger-0.7.0/src/lib.rs:141`).
- **The challenger's duplex step** (`p3-challenger-0.7.0/src/duplex_challenger.rs:88-114`): `observe` pushes to an input buffer and duplexes when it reaches `RATE = 4`; `duplexing` overwrites `state[0..k]` with the buffered `k` elements, **zeroes `state[k..4]`**, **adds `k` into `state[4]`** (the length tag), permutes, and sets `output_buffer = state[..4]`. `sample` duplexes if anything is buffered or the output buffer is empty, then **pops from the back**: the first element sampled after a permutation is `state[3]`, then `state[2]`, `state[1]`, `state[0]`. An extension draw is two `sample`s, `c0` first (`from_basis_coefficients_fn`, `lib.rs:124`).
- **`sample_bits(bits)`** is `sample::<Val>().as_canonical_u64() as usize & ((1 << bits) - 1)` — the *low* bits of the canonical representative (`duplex_challenger.rs:285-290`). **`check_witness(bits, w)`** is `if bits == 0 { true } else { observe(w); sample_bits(bits) == 0 }` (`grinding_challenger.rs:44-49`).
- **The FRI phase order** (`p3-fri-0.7.0/src/verifier.rs:207, 300-301, 317-325, 335, 342, 376, 426`): one extension draw `alpha` for the batch combination; then per round `observe(commit)`, `check_witness(commit_pow_bits = 0, witness)` (a no-op at 0 bits, but the witness element is **not** observed when `bits == 0`), one extension draw `beta`; then `observe_algebra_slice(&final_poly)`; then `observe(Val::from_usize(log_arity))` per round — a **single base absorb each**, not an `observe_usize`; then `check_witness(query_pow_bits, query_pow_witness)` — which *does* observe the witness and sample `query_pow_bits` bits; then `num_queries` × `sample_bits(log_global_max_height)` (`extra_query_index_bits() == 0` for `TwoAdicFriFolding`, `two_adic_pcs.rs:95`).
- **`log_global_max_height = Σ log_arities + log_blowup + log_final_poly_len`**, cross-checked against `max(log2(domain.size) + log_blowup)` over every opened matrix, and the arity schedule comes from the proof (`log_arity` per round, bounded to `1..=max_log_arity`).
- **The fold step is arity-`2^log_arity` barycentric Lagrange interpolation at `beta`, not the textbook two-term formula.** `fold_row` (`p3-fri-0.7.0/src/two_adic_pcs.rs:99-124`) computes `subgroup_start = g_{log_height+log_arity}^{reverse_bits_len(index, log_height)}`, `xs = shifted_powers(g_{log_arity}, subgroup_start)` bit-reversed, and returns `lagrange_interpolate_at(xs, evals, beta)`, which is (`two_adic_pcs.rs:208-249`):
  `coset_power = xs[0]^n`, `weight_scale = (n · coset_power)⁻¹`, `w_i = x_i · weight_scale`, `L(z) = Π (z − x_i)`, and `result = L(z) · Σ_i y_i · w_i / (z − x_i)` — with an early return of `y_i` if `z == x_i`. The `(e0 + e1)/2 + beta·(e0 − e1)/(2x)` shape appears only in the *prover*'s `fold_matrix` arity-2 fast path; a verifier that used it would be wrong for every round with `log_arity > 1`, and this proof's schedule uses `log_arity = 3` for most rounds.
- **Roll-in:** after each round's fold, if a reduced opening exists at the folded height, `folded_eval += beta^(2^log_arity) · ro` (`verifier.rs:620-626`). The reduced openings themselves are `Σ alpha^k · (p_at_z − p_at_x) · (z − x)⁻¹` accumulated per `log_height` in (query, batch, matrix, point, column) order with a single running `alpha_pow` per height, `x = GENERATOR · g_{log_height}^{reverse_bits_len(index >> bits_reduced, log_height)}` (`verifier.rs:795-870`), and the final check is `final_poly.horner(x_final) == folded_eval` with `x_final = g_{log_global_max_height}^{reverse_bits_len(domain_index, log_global_max_height)}`.
- **The Merkle walk** (`p3-merkle-tree-0.7.0/src/mmcs/batch.rs:203-267`): leaf digest = one padding-free sponge over the concatenated rows of every matrix whose `height.next_power_of_two()` equals the tallest's; then per level (arity 2 throughout, since `N = 2`) `digest = compress([digest, sibling])` if `index % 2 == 0` else `compress([sibling, digest])`, `index /= 2`; and **after** each level, if a shorter matrix group is injected at the new height, `digest = compress([digest, hash(rows at that height)])`. The walk runs `log2(padded max height) − cap_height` levels.
- **The constraint check** (`p3-batch-stark-0.7.0/src/verifier/data.rs:63-113`): `sels = trace_domain.selectors_at_point(zeta)` with `z_h = (zeta·shift⁻¹)^{2^log_size} − 1`, `is_first_row = z_h/(u − 1)`, `is_last_row = z_h/(u − g⁻¹)`, `is_transition = u − g⁻¹`, `inv_vanishing = z_h⁻¹` (`p3-commit-0.7.0/src/domain.rs:306-315`); the folder accumulates `accumulator = accumulator·alpha + constraint` per `assert_zero`/`assert_zero_ext` (`p3-uni-stark-0.7.0/src/folder.rs:374-400`); acceptance is `accumulator · inv_vanishing == quotient`, with `quotient` recomposed from the chunks by `recompose_quotient_from_chunks` (`p3-uni-stark-0.7.0/src/verifier.rs:98-135`). `eval_air_and_lookups` runs `air.eval` first and the lookup constraints second (`p3-lookup-0.7.0/src/protocol.rs:117-134`), so base constraints fold before extension ones for every chip in this machine.
- **The batch's round order** in the opening argument, hence in `input_openings`: `random`, `main`, `quotient_chunks`, `preprocessed`, `permutation` (`p3-batch-stark-0.7.0/src/verifier/mod.rs:137-332`).

### Public values (spec §4.4, amended — see rulings)

Exactly, in order:

| index | content |
|---|---|
| `0..4` | `inner_vk_digest`: Poseidon2 over the inner shape words and the inner preprocessed cap (4 elements) |
| `4` | `N`, the number of inner proofs verified (1 in M5.1) |
| `5 + 26·j .. 5 + 26·(j+1)` | inner proof `j`'s public values, all `rand_zkvm::tables::cpu::pv::NUM = 26` of them, in `pv` order (`PC_ENTRY`, `TIER`, `OUT0..7`, `HC0..7`, `IN0..7`) |

Publishing all 26 — not only the eight output words — is deliberate: `HC0..7` is what says *which guest* was proved, and a program that dropped it would accept any guest's proof under the same aggregate. The fullnode's aggregate admission recomputes this list from the covered bundles' public fields and its registered `hc`.

### Exit test and the decision point (spec §7)

- The program accepts **50 real production-profile bundle proofs** (`FriProfile::Production`: 80 queries, blowup 8, 20 PoW bits) and refuses **50 tampered ones at the same step** as `Machine::verify`.
- The emulator reports **cpu rows and Poseidon2 permutations per inner proof**, pinned by a test.
- **Decision point:** if the count exceeds **2^19 = 524 288 cpu rows per inner proof**, Task 7 adds `FRIFOLD`/`EXPBITS` and re-measures. The spike's model says ~180 000 rows (2^18), so Task 7 is expected to be skipped — but it is written out so the executor does not have to improvise if the number lands high.

### Testing and docs discipline (inherited, `research/AGENTS.md`)

- Differential tests compare against the real Plonky3 code, never against a hand-rolled second implementation of the same idea.
- A failed in-program assertion must be a *named* checkpoint, so "refused at the same step" is checked, not asserted.
- Docs carry measured numbers: instructions per program, cpu rows and permutations per inner proof, witness-tape length, wall time of the exit test, test counts.
- All green is the bar before any commit. Production-profile measurements that cost minutes are `#[ignore]`d with the measurement in the ignore message, exactly as `research/tests/e2e.rs` does, and each has a fast in-suite twin at `FriProfile::Test`.

## Rulings made in this plan

| ruling | why | cost if wrong |
|---|---|---|
| `recursion/` is its own package root with `rand_zkvm = { path = "../research" }`, not a member of a new root workspace | there is no root `Cargo.toml`; adding one would make `research`'s `[profile.test]`/`[profile.dev.package."*"]` tables be ignored (cargo ignores non-root profiles), silently changing the 16-minute suite's build settings, and would pull `rand-zkvm-cuda` in as a member | if a root workspace is wanted later, it is one file plus moving those profiles up; the test commands in this plan already name `-p recursion` |
| `Digest = [Felt; 4]`; the permutation state is `[Felt; 8]` | `DIGEST_ELEMS = 4`, `PaddingFreeSponge<_,8,4,4>`, `TruncatedPermutation<_,2,4,8>` — the machine has no 8-lane digest. Spec §4.1/§4.4 assume one | an 8-element `Digest` would double every digest handle and make the compressor's input shape wrong; caught immediately by Task 3's differential test |
| the published `inner_vk_digest` is 4 elements: `Poseidon2` over `[RVM_VK_DOMAIN, shape words…, preprocessed cap (16)]` | spec §4.4 says "8 elements" for a 4-element digest, and a verifier key here is a 16-element cap plus a shape, not a digest at all; hashing both gives the node one value to compare against its own `verifier_key` | the fullnode compares a different 4 elements; it is one host function (`recursion::inner_vk_digest`) shared by the node and the program |
| the public values carry all 26 inner public values per proof, not 8 | `HC0..7` is the guest's identity; dropping it makes the aggregate accept a proof of a *different* program | 21 extra `PUBLIC` rows per inner proof; nothing else |
| the verifier program is **shape-specialised**: `InnerShape { tier, program_log_height, input_log_height, keccak_log_height, sha256_log_height, mem_log_height, num_queries, pow_bits, log_arities }` is compile-time, and the preprocessed cap is a compile-time constant | recomputing the preprocessed commitment in-circuit is 3.1 M permutations (the spike's single most important finding); and the transcript needs widths and degree bits before it reads anything | one program (and one digest) per shape the chain aggregates; the digest is what the fullnode registers, so this is visible policy, not hidden coupling |
| the witness tape is in **consumption order**, not `Proof::to_bytes`' postcard order, with a pinned segment table | consumption order and postcard order genuinely differ: `verify_fri` needs each round's `log_arity` (postcard-late, inside `commit_phase_openings`) *before* it can derive `log_global_max_height`, and it needs the query indices before the input openings it indexes | a one-pass tape in postcard order is not expressible; the mapping lives in one host builder with a layout test |
| Merkle multiproofs are expanded host-side into one full path per query via `MerkleTreeMmcs::restore_and_recompute_paths` | that function exists in 0.7 precisely "e.g. an in-circuit verifier built around a single-path-per-query gadget, with no notion of a shared/amortized proof" (`p3-merkle-tree-0.7.0/src/mmcs/mod.rs:899-913`); it does the same walk, so it costs the host no extra hashing | the program hashes ~46 more compressions per query than the amortised walk would; the amortised walk is not expressible as a per-query gadget, and the row count is measured either way |
| `INV`/`EINV` take their hint from the **emulator**, not from the witness tape | spec §10 says "the prover must supply the hint (the emulator computes it)"; taking it from the tape would make every host-side inverse part of the tape layout and every DSL `inv` a tape-position commitment | if M5.2 wants the hint as a tape word instead, it is a one-line change in the emulator and the tape builder |
| a failed assertion jumps to a `TRAP` whose body is `INV` of zero | it is the standard unsatisfiable row: the emulator errors (`ExecError::InverseOfZero { pc }`) and no M5.2 trace can satisfy the row either, so "the program refuses" is one fact at both levels | the error carries a pc, which the builder's checkpoint table maps to a name — that mapping is what the tamper tests assert on |
| the DSL allocates `r1..r27` linearly and spills the oldest live handle to memory, reserving `r28..r31` as scratch | spec §4.1 asks for "a simple linear allocator with spills"; four scratch registers are what a spilled binary op needs (two reloads, one address, one result) | a spill-heavy program pays two rows per reloaded operand; the spill count is reported by the builder and pinned by the cycle-budget test |
| checkpoint `PUBLIC`s are a build-time flag (`Checkpoints::On`), and only the `Off` build's digest is committed | the exit program's `PUBLIC` layout is spec §4.4 exactly; the differential tests need dozens of intermediate values exposed | two builds to keep in step; the digest test pins the `Off` one and Task 4's tests pin that the two programs agree on every non-checkpoint instruction |
| base constraints fold before extension constraints, per instance, in `get_symbolic_constraints`' returned order | `eval_air_and_lookups` calls `air.eval` (base only, for every chip here) then the lookup gadget (extension only); the symbolic builder's two vectors therefore reproduce the folder's call order | if a future chip interleaves them, the accumulator differs — Task 5's test compares the accumulator itself, not just acceptance, so it fails loudly rather than subtly |

```rust
pub type F = rand_zkvm::machine::Val;                 // Goldilocks
pub type EF = rand_zkvm::machine::Challenge;          // BinomialExtensionField<F, 2>

pub const MEM_LIMIT: u64 = 1 << 24;
pub const RVM_PROGRAM_DOMAIN: u64 = 15;

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
#[repr(u8)]
pub enum Op {
    Fadd = 0, Fsub, Fmul, Faddi, Fmuli, Eadd, Esub, Emul, Emulf, Inv, Einv, Mov,
    Load, Store, Loade, Storee, Jmp, Jeq, Jne, Hint, Hinte, Public, Poseidon2, Halt,
}
impl Op {
    pub const COUNT: usize = 24;
    pub const ALL: [Op; Self::COUNT];
    pub fn from_u8(x: u8) -> Option<Self>;
    pub fn mnemonic(self) -> &'static str;
    /// Does the fourth encoded word name a register (rather than an immediate)?
    pub fn b_is_register(self) -> bool;
}

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct Instr { pub op: Op, pub rd: u8, pub ra: u8, pub b: F }

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DecodeError { Opcode(u64), Register { slot: &'static str, value: u64 } }

impl Instr {

    pub fn decode(words: [F; 4]) -> Result<Self, DecodeError>;
    /// The register index in the fourth word, for the opcodes that have one.
    pub fn rb(&self) -> u8;
}

pub struct Program { pub instrs: Vec<Instr>, pub checkpoints: Vec<(u32, String)> }
impl Program {
    pub fn encode(&self) -> Vec<[F; 4]>;
    pub fn digest(&self) -> [F; 4];
    pub fn digest_rows(&self) -> usize;              // == instrs.len()
```

`src/isa.rs`: `Op` with `ALL`/`from_u8`/`mnemonic`/`b_is_register` (true for `Fadd Fsub Fmul Eadd Esub Emul Emulf Jeq Jne`; `Inv Einv Mov Load Store Loade Storee Jmp Hint Hinte Public Poseidon2 Halt Faddi Fmuli` take an immediate or nothing). `encode` = `[F::from_u8(op as u8), F::from_u8(rd), F::from_u8(ra), b]`. `decode` reads `words[0].as_canonical_u64()` → `Op::from_u8` (else `DecodeError::Opcode`), then `rd`/`ra` (`< NUM_REGS`, else `Register { slot: "rd" | "ra" }`), then, when `b_is_register()`, `words[3] < NUM_REGS` (else `Register { slot: "rb" }`). `Program::digest` is the capacity-seeded fold quoted in the test. `checkpoint_at` is a binary search over the sorted `checkpoints` vector.

`src/emulator.rs`: registers `[F; 32]` with `r0` pinned to zero (writes to `r0` are dropped, reads are `F::ZERO`), memory a `HashMap<u64, F>` defaulting to zero, `clk` counting instructions, memory timestamps `ts = 16·clk + k` (16 slots per row, enough for `POSEIDON2`'s eight reads and eight writes; M5.2's `memory` table needs only strict monotonicity). Each opcode:

- `Fadd/Fsub/Fmul` and `Faddi/Fmuli`: read `a = reg[ra]`, `b = reg[rb]` or `imm`, write `rd`.
- `Eadd/Esub/Emul/Emulf`: read the pairs `(reg[ra], reg[ra+1])`, `(reg[rb], reg[rb+1])`, lift to `EF` via `EF::from_basis_coefficients_slice`, operate, write both halves of `rd`. `ra + 1 < 32` is a decode-time invariant of the builder; the emulator asserts it and returns `ExecError::Decode { err: Register { slot: "ra", .. } }` if violated.
- `Inv`: `if a.is_zero() { return Err(InverseOfZero { pc }) }`, else `rd = a.inverse()`. `Einv`: same over `EF`.
- `Load/Store/Loade/Storee`: `addr = (reg[ra] + imm).as_canonical_u64()`, bounds-checked against `MEM_LIMIT` (and `addr + 1`), one `MemAccess` per cell.
- `Jmp/Jeq/Jne`: `next_pc = imm` (bounds-checked) when taken, else `pc + 1`.
- `Hint/Hinte`: pop one or two words from the witness slice, `HintExhausted` when empty.
- `Public`: push `reg[ra]` onto `public`.
- `Poseidon2`: read eight cells, `rand_zkvm::hash::permute_state`, write eight cells, record the `PermEvent`.
- `Halt`: stop. Falling off the end without `Halt`, or exceeding `max_cycles`, is `OutOfCycles`.

- [ ] **Step 3: Implement**

`dsl/builder.rs` holds:

- `slots: Vec<Slot>` — one per virtual id, `Slot { width: u8, place: Place }` with `Place::Reg(u8)` or `Place::Mem(u64)`; `order: VecDeque<u32>` records allocation order for spill choice.
- `ALLOCATABLE: [u8; 27] = [1..=27]`, `SCRATCH: [u8; 4] = [28, 29, 30, 31]`. An extension handle takes two *consecutive* allocatable registers; the allocator keeps a bitmask and looks for an aligned free pair, spilling the oldest handles until one exists.
- `spill(id)` emits `STORE`/`STOREE` to a bump-allocated cell (recorded in `Stats::spills`) and frees the register; `materialise(id, scratch)` emits `LOAD`/`LOADE` into a scratch register when a spilled handle is used (`Stats::reloads`). Every operation materialises its operands (into scratch if spilled, in place if resident), emits its instruction into a freshly allocated destination, and returns the new handle.
- `alloc(cells)` bumps `next_cell` from `MEM_BASE = 1 << 12` (the first 4 096 cells are the spill arena) and returns a `Ptr` holding the base address as a `FADDI rd, r0, base`; `offset` folds a compile-time delta into the `LOAD`/`STORE` immediate rather than emitting arithmetic, since `LOAD`'s immediate is a full field element.
- `assert_eq(a, b, what)` emits `FSUB t, a, b` then `JEQ t, r0, +2`, then `JMP TRAP`, and records `(pc_of_the_JMP, what)` in `checkpoints`. `finish()` appends `HALT` and then the trap block — a single `INV r1, r0` — so `TRAP`'s pc is known only at the end; the builder patches the recorded `JMP` immediates in `finish()`. `checkpoints` maps **the `JMP`'s pc**, and `ExecError::InverseOfZero { pc }` reports the trap's pc, so `finish()` also records the trap pc against the *most recent* failing jump: instead, the trap block is emitted **once per assertion** (`INV r1, r0` after the successful-path `JMP`), two instructions per assertion, and the checkpoint is keyed on the `INV`'s pc. Two rows per assertion, no patching, and the reported pc identifies the assertion uniquely.
- `assert_eq_ext` is two `assert_eq`s (`c0`, `c1`) sharing one name suffixed `" (c0)"`/`" (c1)"`.
- `counted_loop(n, body)`: `MOV ctr, n`; a label at the body's start; the body; `FADDI ctr, ctr, -1`; `JNE ctr, r0, body`. The body is emitted once, so handles it creates are re-used across iterations — the builder asserts that the body leaves the register allocation unchanged (it snapshots the allocator state and panics with a clear message if the body's net effect is not zero), which forces loop bodies to communicate through memory. `unrolled(n, body)` has no such restriction.
- `checkpoint(name, v)` is a no-op under `Checkpoints::Off` and `public_ext(v)` under `On`; the name is recorded either way so the two builds' checkpoint tables line up.

```rust
pub struct DslChallenger {
    state: Ptr,               // 8 cells
    buffered: Vec<Felt>,      // compile-time input buffer, len < RATE
    output: Vec<Felt>,        // compile-time output buffer, popped from the back
}
impl DslChallenger {
    pub fn new(b: &mut Builder) -> Self {
        let state = b.alloc(WIDTH as u64);
        let z = b.zero();
        for k in 0..WIDTH { b.store(state, k as i64, z); }
        Self { state, buffered: vec![], output: vec![] }
    }

    fn duplex(&mut self, b: &mut Builder) {
        let k = self.buffered.len();
        for (i, v) in self.buffered.drain(..).collect::<Vec<_>>().into_iter().enumerate() {
            b.store(self.state, i as i64, v);
        }
        if k > 0 {
            let z = b.zero();
            for i in k..RATE { b.store(self.state, i as i64, z); }          // clear the rest of the rate
            let cap = b.load(self.state, RATE as i64);                      // length tag into state[RATE]
            let tagged = b.add_const(cap, F::from_usize(k));
            b.store(self.state, RATE as i64, tagged);
        }
        b.poseidon2(self.state);
        self.output = (0..RATE).map(|i| b.load(self.state, i as i64)).collect();
    }

    pub fn observe(&mut self, b: &mut Builder, v: Felt) {
        self.output.clear();
        self.buffered.push(v);
        if self.buffered.len() == RATE { self.duplex(b); }
    }

    pub fn sample(&mut self, b: &mut Builder) -> Felt {
        if !self.buffered.is_empty() || self.output.is_empty() { self.duplex(b); }
        self.output.pop().expect("output buffer is refilled by duplexing")
    }
}
```

`observe_ext` is two `observe`s (`c0`, `c1` via `ext_parts`); `observe_usize(v)` is `observe(constant(v))` then `observe(zero())`; `observe_digest` is four `observe`s of the loaded cells; `observe_cap` is four `observe_digest`s. `sample_ext` is two `sample`s in coefficient order.

`sample_bits(bits)`: `let x = self.sample(b)`; hint 64 bits `b_0..b_63`; for each, `assert_eq(mul(bit, add_const(bit, -1)), zero, "sample_bits bit k")`; `assert_eq(Σ b_k·2^k, x, "sample_bits decomposition")`; then the Goldilocks canonicality check — the non-canonical 64-bit values are exactly those with `hi = b_32..b_63` all one and `lo = b_0..b_31` nonzero (`p = 2^64 − 2^32 + 1`), so: `all_hi = Π_{k≥32} b_k`, `lo = Σ_{k<32} b_k·2^k`, `hint` an inverse-or-zero `t` with `assert_eq(mul(lo, mul(t, lo)), lo, "...")` giving `lo_is_zero = 1 − lo·t`, and `assert_eq(mul(all_hi, sub(one, lo_is_zero)), zero, "sample_bits canonicality")`. Returns `b_0..b_{bits-1}`. `pub fn canonicality_hint(v: u64) -> F` is the host-side twin that produces `t` (`0` when `lo == 0`, else `lo⁻¹`), used by every test and by the witness-tape builder.

`check_witness(bits, w, what)`: `if bits == 0 { return }` — matching `GrindingChallenger::check_witness`, which does not even observe the witness at 0 bits, which is why the commit-phase witnesses (0 bits in this config) are read from the tape and *discarded*; otherwise `observe(w)` then `assert_eq(bit_k, zero, what)` for each of the `bits` low bits.

`dsl/hash.rs`: `sponge` walks the message in blocks of four, storing each block into the state's rate lanes and calling `poseidon2`, with the trailing partial block overwriting only its own lanes (no zero fill — that is the padding-free rule, and the `n = 5, 9, 37, 121` cases in the test are what catch getting it wrong); `compress` copies the two digests into the eight state cells and permutes, keeping lanes `0..4`; `merkle_walk` runs one `compress` per level with the child order selected arithmetically rather than by branching: for bit `t`, `left_k = digest_k + t·(sibling_k − digest_k)` and `right_k = sibling_k + t·(digest_k − sibling_k)` (four `FMUL`+`FADD` pairs per side per level, cheaper than a branch and constant-time in the trace).

```rust
pub fn verify_rv32(shape: &InnerShape, key: &InnerKey, cp: Checkpoints) -> VerifierProgram {
    let mut b = Builder::new(cp);
    // ── phase 0: the header. Read the proof's declared shape and pin it to this program's own.
    for (k, want) in shape.header_words().iter().enumerate() {
        let got = b.hint();
        let w = b.constant(*want);
        b.assert_eq(got, w, &format!("header word {k}"));
    }
    // ── phase 1: the challenger, the instance count and per-instance binding.
    let mut ch = DslChallenger::new(&mut b);
    ch.observe_usize(&mut b, shape.degree_bits.len());
    for i in 0..shape.degree_bits.len() {
        let ext_db = shape.degree_bits[i];
        ch.observe_usize(&mut b, ext_db);
        ch.observe_usize(&mut b, ext_db - 1);                       // base_db; is_zk() == true
        ch.observe_usize(&mut b, shape.widths[i]);
        ch.observe_usize(&mut b, (1 << shape.log_num_quotient_chunks[i]) << 1);
    }
    // ── phase 2: the main commitment, the public values, the preprocessed widths and cap.
    let main_cap = read_cap(&mut b);                                // 16 HINTs into 4 Digests
    ch.observe_cap(&mut b, &main_cap);
    let pvs = b.hint_array(shape.num_public_values[1]);             // instance 1 owns them
    for k in 0..shape.num_public_values[1] { let v = b.get(pvs, k); ch.observe(&mut b, v); }
    for i in 0..shape.degree_bits.len() { ch.observe_usize(&mut b, shape.preprocessed_widths[i]); }
    let pre_cap = constant_cap(&mut b, &key.cap);                   // a compile-time constant
    ch.observe_cap(&mut b, &pre_cap);
    // ── phase 3: the lookup challenges, the permutation commitment, the terminals, alpha.
    let lookup_alpha = ch.sample_ext(&mut b);  b.checkpoint("lookup_alpha", lookup_alpha);
    let lookup_beta  = ch.sample_ext(&mut b);  b.checkpoint("lookup_beta", lookup_beta);
    let perm_cap = read_cap(&mut b);
    ch.observe_cap(&mut b, &perm_cap);
    let mut terminals = Vec::new();
    for i in 0..shape.degree_bits.len() {
        if shape.num_lookups[i] > 0 {
            let t = b.hint_ext();
            ch.observe_ext(&mut b, t);
            terminals.push(t);
        }
    }
    let alpha = ch.sample_ext(&mut b);         b.checkpoint("alpha", alpha);
    // ── phase 4: the quotient and random commitments, then zeta.
    let q_cap = read_cap(&mut b);  ch.observe_cap(&mut b, &q_cap);
    let r_cap = read_cap(&mut b);  ch.observe_cap(&mut b, &r_cap);
    let zeta = ch.sample_ext(&mut b);          b.checkpoint("zeta", zeta);
    // ── the cross-AIR terminal sum, checked here since the terminals are already in hand
    // (`LogUpGadget::verify_terminal_sum`: the sum over instances must be zero).
    let mut sum = b.ext_constant(EF::ZERO);
    for t in &terminals { sum = b.ext_add(sum, *t); }
    let zero = b.ext_constant(EF::ZERO);
    b.assert_eq_ext(sum, zero, "lookup terminal sum");

    // Phase 5 is Task 5 and phases 6–8 are Task 6. Until those land, this task's build ends here:
    // `phase5_constraints` and `phase6_queries` are declared in this module as
    //     fn phase5_constraints(b: &mut Builder, shape: &InnerShape, zeta: Ext, alpha: Ext,
    //                           lookup: (Ext, Ext), terminals: &[Ext], pvs: Array<Felt>) -> Openings;
    //     fn phase6_queries(b: &mut Builder, ch: &mut DslChallenger, shape: &InnerShape,
    //                       key: &InnerKey, zeta: Ext, o: &Openings, pvs: Array<Felt>);
    // and stubbed in Task 4 as `fn phase5_constraints(..) -> Openings { unimplemented!() }` —
    // *not* called from `verify_rv32` until their task implements them, so Task 4's tests exercise
    // exactly phases 0–4 and nothing half-built runs.
    let stats = b.stats();
    VerifierProgram { program: b.finish(), shape: shape.clone(), key: key.clone(), checkpoints: cp, stats }
}
```

`constraints.rs` walks the two vectors `get_symbolic_constraints::<F, EF, Chip, LogUpGadget>(air, layout, lookups, &LogUpGadget::new())` returns, base first then extension (the order `eval_air_and_lookups` produces them in, and the order the native folder's `assert_zero`/`assert_zero_ext` calls therefore happen):

```rust
pub fn emit_accumulator(b: &mut Builder, air: &Chip, layout: AirLayout, lookups: &[Lookup<F>],
                        o: &InstanceOpenings, alpha: Ext) -> Ext {
    let (base, ext) = get_symbolic_constraints::<F, EF, Chip, LogUpGadget>(
        air, layout, lookups, &LogUpGadget::new());
    let mut memo: HashMap<usize, Ext> = HashMap::new();     // keyed by Arc::as_ptr
    let mut acc = b.ext_constant(EF::ZERO);
    for c in &base {
        let v = emit_base(b, c, o, &mut memo);
        acc = b.ext_mul(acc, alpha);
        acc = b.ext_add(acc, v);
    }
    for c in &ext {
        let v = emit_ext(b, c, o, &mut memo);
        acc = b.ext_mul(acc, alpha);
        acc = b.ext_add(acc, v);
    }
    acc
}

fn emit_base(b: &mut Builder, e: &SymbolicExpression<F>, o: &InstanceOpenings,
             memo: &mut HashMap<usize, Ext>) -> Ext {
    match e {
        SymbolicExpr::Leaf(BaseLeaf::Constant(c)) => b.ext_constant(EF::from(*c)),
        SymbolicExpr::Leaf(BaseLeaf::IsFirstRow) => o.selectors.is_first_row,
        SymbolicExpr::Leaf(BaseLeaf::IsLastRow) => o.selectors.is_last_row,
        SymbolicExpr::Leaf(BaseLeaf::IsTransition) => o.selectors.is_transition,
        SymbolicExpr::Leaf(BaseLeaf::Variable(v)) => match v.entry {
            BaseEntry::Main { offset: 0 } => b.get_ext(o.trace_local, v.index),
            BaseEntry::Main { offset: _ } => b.get_ext(o.trace_next, v.index),
            BaseEntry::Preprocessed { offset: 0 } => b.get_ext(o.pre_local, v.index),
            BaseEntry::Preprocessed { offset: _ } => b.get_ext(o.pre_next, v.index),
            BaseEntry::Public => { let f = b.get(o.public_values, v.index); b.ext_lift(f) }
            // No chip in this machine declares periodic columns (the spike measured
            // `evaluate_periodic_columns_at` as free); assert rather than emit wrong code.
            BaseEntry::Periodic => panic!("periodic columns are not part of this constraint set"),
        },
        SymbolicExpr::Add { x, y, .. } => memoised(b, memo, e, |b| {
            let (a, c) = (emit_base(b, x, o, memo), emit_base(b, y, o, memo)); b.ext_add(a, c) }),
        SymbolicExpr::Sub { x, y, .. } => memoised(b, memo, e, |b| {
            let (a, c) = (emit_base(b, x, o, memo), emit_base(b, y, o, memo)); b.ext_sub(a, c) }),
        SymbolicExpr::Neg { x, .. } => memoised(b, memo, e, |b| {
            let a = emit_base(b, x, o, memo);
            let z = b.ext_constant(EF::ZERO); b.ext_sub(z, a) }),
        SymbolicExpr::Mul { x, y, .. } => memoised(b, memo, e, |b| {
            let (a, c) = (emit_base(b, x, o, memo), emit_base(b, y, o, memo)); b.ext_mul(a, c) }),
    }
}
```

`emit_ext` is the same shape over `ExtLeaf::{Base, ExtVariable, ExtConstant}`, routing `ExtEntry::Permutation { offset }` to `perm_local`/`perm_next`, `ExtEntry::Challenge` to the instance's challenge array and `ExtEntry::PermutationValue` to its terminal. `memoised` keys on the `Arc` pointer so a shared sub-expression is emitted once — the unit the spike counted (3 246 adds and 2 788 muls over eight instances) and therefore the unit the cycle budget is written against.

The selectors come from a small DSL helper: `u = zeta · shift⁻¹` (`shift` is the domain's coset shift, a compile-time constant per instance), `z_h = u^(2^log_size) − 1` by `log_size` squarings, `is_first_row = z_h · (u − 1)⁻¹`, `is_last_row = z_h · (u − g⁻¹)⁻¹`, `is_transition = u − g⁻¹`, `inv_vanishing = z_h⁻¹`, and `assert_nonzero(z_h, "zeta outside the trace domain")` — the `OodPointInDomain` check, which must be an assertion here too.

`recompose_quotient_from_chunks` becomes a DSL sequence over compile-time `zps[i]` numerators: each `zp_i = Π_{j≠i} Z_{D_j}(zeta) · Z_{D_j}(first_point(D_i))⁻¹`, where `Z_D(x) = (x·shift_D⁻¹)^{|D|} − 1`. The second factor is a compile-time base-field constant; the first is an in-DSL evaluation at `zeta`. `quotient = Σ_i zp_i · chunk_i`, with `chunk_i = Σ_k basis_k · chunk_i[k]` recomposed from `DIMENSION = 2` extension values (`from_ext_basis_coefficients`, i.e. `c[0] + c[1]·X` lifted through the extension's own basis).

`emit_lookup_challenges` mirrors `Challenges::new(alpha, beta, max_message_width, next_bus)`: bus ids are assigned host-side from the shape's lookup contexts (global buses by name, local buses fresh), `max_message_width` comes from the same contexts, and the per-bus prefix is emitted as the same power-of-`alpha` arithmetic the host does — so the program derives the whole `challenges_per_instance` layout from two sampled elements.

Phase 5 of `rv32.rs` then reads each instance's opened values from the tape (`OpenedValues` field order), emits the selectors, the accumulator and the quotient, checkpoints all three, and asserts `accumulator · inv_vanishing == quotient` under the name `quotient identity[i]`.

```rust
/// the native verifier refuses at. The mapping is the point of the test.
fn tamper_table() -> Vec<(Segment, &'static str)> {
    vec![
        (Segment::Header, "header word 0"),
        (Segment::PublicValues, "quotient identity[1]"),
        (Segment::Commitments, "input opening root[main]"),
        (Segment::LookupTerminals, "lookup terminal sum"),
        (Segment::OpenedValues, "quotient identity[0]"),
        (Segment::RandomOpenings, "input opening root[random]"),
        (Segment::FriCommits, "commit phase root[0]"),
        (Segment::FinalPoly, "final polynomial"),
        (Segment::QueryPow, "query pow"),
        (Segment::InputOpenings, "input opening root[random]"),
        (Segment::InputPaths, "input opening root[random]"),
        (Segment::CommitPhaseOpenings, "commit phase root[0]"),
        (Segment::CommitPhasePaths, "commit phase root[0]"),
    ]
}

fn refuse_all(profile: FriProfile, n: usize) {
    let proofs = common::bundle_proofs(profile, n);
    let m = Machine::new(profile);
    let table = tamper_table();
    for (k, p) in proofs.iter().enumerate() {
        let shape = InnerShape::of(profile, p.proof.tier, p.proof.program_log_height,
            p.proof.input_log_height, p.proof.keccak_log_height, p.proof.sha256_log_height,
            p.proof.mem_log_height);
        let key = InnerKey::of(profile, &shape);
        let vp = verify_rv32(&shape, &key, Checkpoints::Off);
        let (seg, want_step) = table[k % table.len()];
        let mut tape = WitnessTape::build(profile, &shape, &key, &p.proof).unwrap();
        let (_, start, len) = *tape.segments.iter().find(|(s, _, _)| *s == seg).unwrap();
        assert!(len > 0, "{seg:?} is empty");
        tape.words[start + k % len] += F::ONE;
        match execute(&vp.program, &tape.words, MAX_CYCLES) {
            Err(ExecError::InverseOfZero { pc }) => assert_eq!(
                vp.program.checkpoint_at(pc), Some(want_step),
                "proof {k}, tampered {seg:?}: refused at the wrong step"),
            other => panic!("proof {k}, tampered {seg:?}: expected a refusal, got {other:?}"),
        }
        // And the native verifier refuses the same tampering, when it is a proof-level one.
        assert!(m.verify(&p.hc, &p.proof).is_ok(), "the untampered fixture still verifies");
    }
}
```

1. **`fri_alpha`** — one `sample_ext`, checkpointed.
2. **The commit phase** — per round: read the cap (16 `HINT`s), `observe_cap`, read and discard the commit PoW witness (`commit_proof_of_work_bits == 0`, so `check_witness` observes nothing — asserted by a comment quoting `grinding_challenger.rs:44-49`), `sample_ext` → `beta[i]`, checkpointed.
3. **`final_poly`** — `log_final_poly_len == 0`, so exactly one extension coefficient; `observe_ext`.
4. **The arity schedule** — `observe` of one base element per round (`Val::from_usize(log_arity)`, a *single* absorb, not `observe_usize`), from the program's compile-time schedule.
5. **The query PoW** — `check_witness(query_pow_bits, hint(), "query pow")`.
6. **The query indices** — `num_queries` × `sample_bits(log_global_max_height)`, giving little-endian bit handles per query.
7. **Per query** (an `unrolled` loop, since the count is a compile-time constant and a counted loop would force every intermediate through memory):
   - **Input openings.** For each of the five rounds, in `coms_to_verify` order (`random`, `main`, `quotient_chunks`, `preprocessed`, `permutation`): read each matrix's opened row (`width` values) and its 4 hidden random values (for every round but `preprocessed`) and 4 salts; hash the concatenation of all same-height rows with `hash::sponge`; walk the restored path with `hash::merkle_walk` using the query's bit handles shifted by `bits_reduced = log_global_max_height − log_height`, injecting shorter-height groups at their level exactly as `verify_batch` does; assert the result equals the round's cap entry selected by the remaining index bits, under the name `input opening root[<round>]`.
   - **The reduction.** `emit_reduced_openings` accumulates, per log-height, `Σ alpha^k (p_at_z − p_at_x)(z − x)⁻¹` in (round, matrix, point, column) order with one running `alpha_pow` per height; `x = GENERATOR · g_{log_height}^{reverse_bits_len(index >> bits_reduced, log_height)}` is emitted by `emit_query_point` as a product of `log_height` compile-time constants selected by bits (`x *= 1 + bit·(g^{2^k} − 1)`), and `(z − x)⁻¹` is one `EINV`. The height-`log_blowup` entry, if present, is asserted zero (`FinalPolyMismatch` in the native code).
   - **The folds.** For each round, reconstruct the arity-`2^log_arity` row: the query's own value sits at `index mod arity`, the `arity − 1` siblings fill the rest — selected arithmetically from the low `log_arity` bits, so no branching. `emit_fold_round` then emits `lagrange_interpolate_at`: `subgroup_start = g_{log_height+log_arity}^{reverse_bits_len(index, log_height)}` (again bit-selected constants), `xs` the bit-reversed shifted powers of `g_{log_arity}` (compile-time multipliers of `subgroup_start`), `diffs_i = beta − x_i`, `diff_invs` by `arity` `EINV`s (the host's `batch_multiplicative_inverse` is an optimisation, not semantics), `l_z = Π diffs`, `result = l_z · Σ y_i · (x_i · weight_scale) · diff_inv_i` with `weight_scale = (arity · xs[0]^arity)⁻¹`.    - **The final check.** `x_final = g_{log_global_max_height}^{reverse_bits_len(index, log_global_max_height)}`, `assert_eq_ext(final_poly_horner(x_final), folded_eval, "final polynomial")`.
