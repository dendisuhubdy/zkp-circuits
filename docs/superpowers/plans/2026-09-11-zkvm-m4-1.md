# zkVM Milestone 4.1 Implementation Plan — compiled guests, flat-binary loader, bound `READ_INPUT`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a `no_std` Rust guest, built with the real `riscv32im-unknown-none-elf` target and converted to a flat binary, load and prove under `R_exec` exactly like a hand-assembled one — and close the one open soundness gap M2 left behind: `READ_INPUT` today returns an unconstrained, prover-chosen word on every call, with no two reads of the same index tied together (`docs/03-privacy.md`). M4.1 adds `Program::from_flat_binary`/`to_flat_binary` (the loader), a `guest-sdk` crate plus a linker script and a committed compiled `fib` guest (the toolchain), and a new `input` witness table + `INPUT_WORD` bus that binds every `READ_INPUT` to a Poseidon2 commitment `H_IN` over the whole private-input vector — mirroring the M3.4 program-digest mechanism (`hc`) exactly, one input table row per committed word, one digest row per four.

**Architecture:** Two independent, purely additive pieces (the loader, the toolchain) and one constraint-set change (the input commitment) landing on top of the M3.4 machine at `research`'s current HEAD (`819ba11`). The loader is host-side only (`isa.rs`), touching no AIR. The toolchain is a new crate (`guest-sdk`) plus a new, workspace-excluded build directory (`guests-compiled/`) that never needs a RISC-V toolchain to *test* (only to *regenerate* the committed `.bin`). The input commitment reuses the cpu table's existing digest-row machinery (`IS_DIGEST`/`DIGEST_LAST`/`DHVL`/`DHIMAX`/`DINV`, `docs/02-tables-and-buses.md`'s M3.4 section) for a second, sequential digest region (`IS_INDIGEST`) fed by a new `input` witness table over a new `INPUT_WORD` lookup bus, and retargets `SYS_READ` rows to consume from that same bus instead of leaving their return value unconstrained. This is a hard fork of the constraint set (`pv::NUM` grows, the batch grows from 7 to 8 AIRs, `Proof` gains a field) — every vendored consumer (the fullnode) updates in lockstep; see this plan's final section.

**Tech Stack:** Rust `1.98.1` (pinned by `research/rust-toolchain.toml`; every command below is `cargo +1.98.1 ...` to make that explicit), Plonky3 `=0.7.0`, target `riscv32im-unknown-none-elf` (Task 2 only) with the `llvm-tools` rustup component.

**Spec:** `docs/superpowers/specs/2026-09-11-zkvm-m4-design.md`, §2 (M4.1) plus §6–8 (binding for this plan); `research/AGENTS.md` (invariants); `research/docs/01-isa.md`, `02-tables-and-buses.md`, `03-privacy.md`, `05-roadmap.md`.

- **Constraint degree cap 8**: `research/AGENTS.md` and `docs/02-tables-and-buses.md`'s "Constraint degree budget" section — this config's ceiling (`log_blowup = 3`, `is_zk = 1`) is `max_degree ≤ 8`, pinned by `tests/tables.rs::alu_max_constraint_degree_is_pinned`. Every new constraint in Task 3 must stay at or under the degree of the existing digest-row machinery it mirrors (verified in that same test, extended).
- **Every bus message column must be constrained on every row kind that sends it** (`research/AGENTS.md` invariant 1) — checked explicitly below for the `input` table's `INPUT_WORD` provide, the cpu table's `IS_INDIGEST` absorb, and the `SYS_READ` consume.
- **A bus count must be forced to zero wherever the message columns are unconstrained** (`research/AGENTS.md` invariant 2) — the `input` table's `MULT_READ` is forced to 0 on padding rows explicitly (Task 3, Step 2), not left to the multiplicity formula's `IS_REAL` factor alone (that factor already zeroes the *bus count*, but the AGENTS.md lesson from the ALU padding-row bug is to pin the *column* too, and Task 3's cheating test (e) specifically exercises the gap that would exist without it).
- **The emulator is the reference semantics**: `research/src/emulator.rs` — if the AIR and the emulator disagree, the AIR is wrong. Task 3 relies on `emulator::execute`'s existing `ExecError::InputIndex` (an out-of-range `READ_INPUT` already errors there) rather than adding a new variant — see Task 3's ambiguity note.
- **`rejects()` test discipline** (`research/AGENTS.md`, `tests/cheating.rs`): a tamper counts as caught only via a `CONSTRAINT_PANIC` (`"constraints not satisfied on row"`), a `LOOKUP_BALANCE_PANIC` (`"Lookup mismatch ("`), or a `VerifyError`. Every new cheating test in Task 3 is written against `rejects()`, never a bare `assert!`/`panic!` on its own.
- **One fixed message length per hash domain** (`research/AGENTS.md`): `H_IN`'s length (`n_in`, the number of committed input words) is folded into the sponge's capacity lanes before any word is absorbed, exactly like `hc`'s `[HC_DOMAIN, base_pc, len]` header — this is what stops a padding-free sponge from letting two different `n_in` collide via trailing zero words, and it is why Task 3 seeds `[IN_DOMAIN, n_in, 0]` rather than absorbing `n_in` as an ordinary message word.
- **Docs carry measured numbers** (`research/AGENTS.md`): every "measure and record" step below names the exact command to run and the doc section to update; do not carry an estimate into a doc as if it were measured.
- **Commit style**: `research: <area> — <what>` (`git log` in `research/`), one logical change per commit, docs updates riding with the change they describe. Every task below ends with the exact commit command.

### Task 1: Flat-binary loader (`isa.rs`)

`Program::from_flat_binary`/`to_flat_binary` — the host-side half of the M4.1 toolchain. No AIR, no emulator change: a `Program` built by the loader is byte-for-byte the same type `Instr::decode`/`program_trace` already trust, so every downstream table is untouched. This task is fully independent of Task 3 and can be built, tested and committed first.

```rust
// isa.rs
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum LoadError {
    /// `bytes` was empty.
    Empty,
    /// `bytes.len()` was not a multiple of 4.
    Length(usize),
    /// `base_pc % 4 != 0`.
    BasePc(u32),
    /// The image decodes to more words than the program table can ever hold
    /// (`(1 << program::MAX_LOG_HEIGHT) - 1`, `docs/02-tables-and-buses.md`'s program-height note).
    TooLong(usize),
    /// Word at `index` (0-based, i.e. `base_pc + 4*index`) does not decode.
    Decode { index: usize, word: u32, err: DecodeError },
}

impl Program {
    pub fn from_flat_binary(base_pc: u32, bytes: &[u8]) -> Result<Program, LoadError>;
    pub fn to_flat_binary(&self) -> Vec<u8>;
}
```

Consumes: `Instr::decode` (existing), `tables::program::MAX_LOG_HEIGHT` (existing, read-only). Produces: a `Program` identical in shape to one built by `Program::new`/`Assembler::assemble` — every other table, the emulator, and `Machine::prove`/`verify` see no difference between a loaded and a hand-assembled program.

- [ ] **Step 1 — `LoadError` and `from_flat_binary`.** In `research/src/isa.rs`, immediately after `impl Program { .. }`'s closing brace (after `code_hash`), add:

  ```rust
  #[derive(Clone, Copy, Debug, PartialEq, Eq)]
  pub enum LoadError {
      Empty,
      Length(usize),
      BasePc(u32),
      TooLong(usize),
      Decode { index: usize, word: u32, err: DecodeError },
  }

  impl Program {
      /// The M4.1 flat-binary loader: little-endian words, `base_pc % 4 == 0`, every word must
      /// decode (`Instr::decode`, the same check `program_trace` enforces as a panic on a
      /// hand-built `Program` — this is the friendly, `Result`-returning path in front of it).
      /// `MAX_LOG_HEIGHT` bounds the program table's height a proof can ever declare
      /// (`tables::program::program_log_height`'s doc comment); `pad_height(len+1,
      /// MIN_HEIGHT)` needs `len + 1 <= 2^MAX_LOG_HEIGHT`, so `len` up to `2^MAX_LOG_HEIGHT - 1`
      /// is the largest image this loader — or any other program construction path — can ever
      /// turn into a provable `Program`.
      pub fn from_flat_binary(base_pc: u32, bytes: &[u8]) -> Result<Program, LoadError> {
          if bytes.is_empty() { return Err(LoadError::Empty); }
          if bytes.len() % 4 != 0 { return Err(LoadError::Length(bytes.len())); }
          if base_pc % 4 != 0 { return Err(LoadError::BasePc(base_pc)); }
          let words: Vec<u32> = bytes.chunks_exact(4).map(|c| u32::from_le_bytes([c[0], c[1], c[2], c[3]])).collect();
          let max_words = (1usize << crate::tables::program::MAX_LOG_HEIGHT) - 1;
          if words.len() > max_words { return Err(LoadError::TooLong(words.len())); }
          for (index, &word) in words.iter().enumerate() {
              if let Err(err) = Instr::decode(word) { return Err(LoadError::Decode { index, word, err }); }
          }
          Ok(Program::new(base_pc, words))
      }

      /// The inverse: little-endian bytes of every word, `base_pc` carried only in the
      /// `Program` itself (a flat binary has no header — the loader's caller supplies
      /// `base_pc` out of band, exactly `guests::compiled::fib`'s `0x1000` literal does).
      pub fn to_flat_binary(&self) -> Vec<u8> {
          let mut out = Vec::with_capacity(self.words.len() * 4);
          for w in &self.words { out.extend_from_slice(&w.to_le_bytes()); }
          out
      }
  }
  ```

  `DecodeError` and `Instr::decode` are already `pub`/`pub(crate)`-visible from this module; no new imports needed.

  `guest-sdk/src/lib.rs`:

  ```rust
  //! Syscall wrappers and the guest entry point for RV32IM binaries this machine can load and
  //! prove (`Program::from_flat_binary`, `research/src/isa.rs`). Every wrapper matches
  //! `research/docs/01-isa.md`'s syscall ABI exactly: syscall number in `a7`, first argument in
  //! `a0`, a second argument (only `POSEIDON2` needs one) in `a1`, a returned value in `a0`.
  #![no_std]

  #[cfg(not(target_arch = "riscv32"))]
  compile_error!("guest-sdk only builds for riscv32im-unknown-none-elf");

  const SYS_HALT: u32 = 0;
  const SYS_WRITE_OUTPUT: u32 = 1;
  const SYS_READ_INPUT: u32 = 2;
  const SYS_POSEIDON2: u32 = 3;

  /// Returns private input word `idx` — bound, since milestone 4.1, to the proof's `H_IN`
  /// commitment (`research/docs/03-privacy.md`): two calls with the same `idx` are guaranteed
  /// to return the same word, and `idx >= n_in` (the number of words the caller committed) can
  /// never be satisfied at all.
  #[inline(always)]
  pub fn read_input(idx: u32) -> u32 {
      let out: u32;
      unsafe {
          core::arch::asm!(
              "ecall",
              in("a7") SYS_READ_INPUT,
              in("a0") idx,
              lateout("a0") out,
              options(nostack),
          );
      }
      out
  }

  #[inline(always)]
  pub fn write_output(slot: u32, word: u32) {
      unsafe {
          core::arch::asm!(
              "ecall",
              in("a7") SYS_WRITE_OUTPUT,
              in("a0") slot,
              in("a1") word,
              options(nostack),
          );
      }
  }

  /// `ptr`: a **word address** (already divided by 4, `research/docs/01-isa.md`'s `MEM_ADDR`
  /// convention), pointing at `n` words to hash in place with the `POSEIDON2` sponge, `ptr..
  /// ptr+8` overwritten with the digest. `n <= 4096` (`isa::POSEIDON2_MAX_WORDS`).
  #[inline(always)]
  pub fn poseidon2(ptr: *mut u32, n: usize) {
      unsafe {
          core::arch::asm!(
              "ecall",
              in("a7") SYS_POSEIDON2,
              in("a0") ptr as u32,
              in("a1") n as u32,
              options(nostack),
          );
      }
  }

  #[inline(always)]
  pub fn halt() -> ! {
      unsafe {
          core::arch::asm!(
              "ecall",
              in("a7") SYS_HALT,
              options(nostack, noreturn),
          );
      }
  }

  /// A panicking guest halts with output slot 7 set to a fixed sentinel, rather than looping
  /// forever or executing whatever undefined instruction `core::panic` would otherwise fall
  /// through to (there is no `abort`/`unreachable` intrinsic lowering safe on this target
  /// without one).
  #[panic_handler]
  fn panic(_info: &core::panic::PanicInfo) -> ! {
      write_output(7, 0xdead_beef);
      halt();
  }

  // `_start`: sets `sp` to the linker-provided `__stack_top` (`guest.ld`) and calls the guest's
  // own `main`. `la`/`call` lower to `auipc`+`addi`/`auipc`+`jalr` — both RV32I, both in this
  // machine's decoder — no pseudo-instruction here needs an extension the target lacks.
  core::arch::global_asm!(
      ".section .text._start",
      ".global _start",
      "_start:",
      "    la sp, __stack_top",
      "    call main",
      // Defense in depth: if `main` ever returns instead of calling `halt()` itself, halt here
      // rather than falling into whatever bytes follow in `.text`.
      "    li a7, 0",
      "    ecall",
  );
  ```

  `guest-sdk/guest.ld`:

  ```
  ENTRY(_start)

  MEMORY {
    RAM (rwx) : ORIGIN = 0x1000, LENGTH = 0x00100000
  }

  SECTIONS {
    . = 0x1000;
    .text : {
      *(.text._start)
      *(.text .text.*)
    } > RAM
    .rodata : { *(.rodata .rodata.*) } > RAM
    .data : { *(.data .data.*) } > RAM
    .bss (NOLOAD) : { *(.bss .bss.*) *(COMMON) } > RAM
    . = ALIGN(4);
    . = . + 0x10000; /* 64 KiB stack */
    __stack_top = .;
    /DISCARD/ : { *(.comment) *(.eh_frame*) *(.riscv.attributes) *(.note*) }
  }
  ```

  Base `0x1000` matches the guest entry convention the spec names (`pc = base_pc`); `.text`, `.rodata`, `.data` land contiguously starting there (a flat binary has no section headers, so `llvm-objcopy -O binary` only works because everything is placed in one contiguous, ascending-address image — a gap between sections would silently zero-fill, which is harmless here since RAM starts zeroed anyway, but keeping them contiguous keeps the `.bin` small). `.bss` is `NOLOAD` — its bytes are never part of the image at all (`docs/01-isa.md`: "Data memory ... starts entirely zeroed"), so the flat binary ends at `.data`'s last byte, not at `__stack_top`; the stack region exists only in the linker's address-space accounting, never as image bytes.

  ```rust
  #![no_std]
  #![no_main]

  use guest_sdk::{halt, read_input, write_output};

  fn fib(n: u32) -> u32 {
      let (mut a, mut b) = (0u32, 1u32);
      for _ in 0..n {
          let c = a.wrapping_add(b);
          a = b;

      }

  /// Reads `n` from input slot 0, writes `fib(n)` to output slot 0 — the same function
  /// `guests::fib` computes by hand-assembled loop (`research/src/guests.rs`), so the two are
  /// directly comparable in Step 4's test.
  ```

### Task 3: Input commitment — the `input` table, `INPUT_WORD` bus, bound `READ_INPUT`

The core of M4.1. Mirrors the M3.4 program-digest mechanism (`research/src/tables/program.rs`'s module doc, `docs/02-tables-and-buses.md`'s "M3.4: the digest-row prefix" section, `research/src/hash.rs::program_digest`) end to end: a witness table providing one bus message per committed word, a second cpu-table digest region absorbing that bus into a Poseidon2 sponge and publishing the result, and — new here, since `PROGRAM_WORD` only ever has one consumer (the digest) while `INPUT_WORD` has two — `SYS_READ` rows consuming from the same bus the digest absorbs from, so a read and the commitment are proved against the same underlying table instead of two independently-trusted paths.

  ```rust
  /// H_IN (M4.1): the in-circuit commitment to the guest's private-input vector, exactly what
  /// `tables::cpu`'s `IS_INDIGEST` rows compute and `pv::IN0..IN7` publish — the `hc`/
  /// `program_digest` mechanism, mirrored: capacity lanes seeded with `[IN_DOMAIN, n_in, 0]`
  /// (only two real header words, since there is no `base_pc` analogue for a flat input
  /// vector) before any input word is absorbed, then `⌈n_in/4⌉` blocks of up to 4 words each —
  /// at least one block even when `n_in == 0`, so `H_IN(&[])` is not the all-zero digest
  /// (the same "the header alone still costs one permutation" argument `program_digest`'s doc
  /// comment makes).
  pub fn input_digest(inputs: &[u32]) -> [u32; 8] {
      let blocks = input_digest_rows(inputs);
      let state = blocks.last().expect("input_digest_rows always returns at least one block").state_out;
      split_digest([state[0], state[1], state[2], state[3]])
  }

  /// One `tables::cpu` `IS_INDIGEST` row's worth of absorb data — the M4.1 twin of
  /// `program_digest_rows`, reusing the same `DigestBlock` shape.
  pub fn input_digest_rows(inputs: &[u32]) -> Vec<DigestBlock> {
      let mut state = [Val::ZERO; 8];
      state[4] = Val::from_u32(crate::notes::domain::IN);
      state[5] = Val::from_u32(inputs.len() as u32);
      // state[6] stays 0 — H_IN's header is [IN_DOMAIN, n_in, 0], one fewer real word than
      // hc's [HC_DOMAIN, base_pc, len] (there is no base-address analogue here).
      let n = inputs.len();
      let rows = n.div_ceil(4).max(1);
      let mut out = Vec::with_capacity(rows);
      for i in 0..rows {
          let state_in = state;
          let mut block_words = [0u32; 4];
          let mut active = [false; 4];
          let mut merged = state;
          for k in 0..4 {
              let idx = i * 4 + k;
              if idx < n {
                  block_words[k] = inputs[idx];
                  active[k] = true;
                  merged[k] = Val::from_u32(inputs[idx]);
              }
          }
          let left_before = (n - i * 4) as u32;
          state = permute_state(merged);
          out.push(DigestBlock { idx: i as u32, left_before, words: block_words, active, state_in, state_out: state });
      }
      out
  }

  /// `⌈n_inputs/4⌉`, at least 1 — the number of cpu-table `IS_INDIGEST` rows `H_IN` costs to
  /// prove, the exact `input_digest_rows(inputs).len()` without building the `Vec` (used by
  /// `Machine::build_traces`'s cycle-budget check before the full digest is computed).
  pub fn input_digest_row_count(n_inputs: usize) -> usize { n_inputs.div_ceil(4).max(1) }
  ```

  ```rust
  //! M4.1: the `input` witness table — one row per committed private-input word, providing
  //! `(IDX, WORD)` on `INPUT_WORD`. Mirrors `tables::program`'s `(PC, WORD)`/`PROGRAM_WORD`
  //! shape exactly, with one difference `PROGRAM_WORD` never needed: `INPUT_WORD` has *two*
  //! consumers (the cpu table's `IS_INDIGEST` digest rows, and its `SYS_READ` rows), so a row's
  //! provided count is `IS_REAL * (1 + MULT_READ)` — the mandatory 1 the digest always claims,
  //! plus however many times the guest actually reads that index (`MULT_READ`, a free but
  //! LogUp-balance-checked witness value). Any real row the digest does not cover (an honest
  //! table always has real rows exactly `{0, .., n_in-1}`, matching what the digest demands —
  //! see below) supplies an unclaimable extra "1" that can never balance, which is what forces
  //! the real-row count to equal `n_in` exactly, the same set-equality argument
  //! `docs/02-tables-and-buses.md`'s "`hc` binds the whole executable program" section makes
  //! for `program`'s `MULT_WORD = VALID`.
  use super::{bus, F};
  use crate::emulator::{CycleEvent, Syscall};
  use p3_air::{Air, AirBuilder, BaseAir, WindowAccess};
  use p3_field::{Field, PrimeCharacteristicRing};
  use p3_lookup::InteractionBuilder;

      pub const IDX: usize = 0;
      pub const WORD: usize = 1;
      pub const IS_REAL: usize = 2;
      /// How many times `SYS_READ` actually consumes this row's `(IDX, WORD)`, beyond the one
      /// mandatory copy the `IS_INDIGEST` digest rows always claim. A free witness value, but
      /// pinned to reality by the `INPUT_WORD` bus balance: if it disagrees with the true read
      /// count, the SYS_READ side's demand and this row's supply stop matching.
      pub const MULT_READ: usize = 3;
      pub const WIDTH: usize = 4;
  }

  pub const MIN_HEIGHT: usize = 4;
  pub const MIN_LOG_HEIGHT: u8 = 2; // 1 << 2 == MIN_HEIGHT

  /// private-input words, comfortably past any guest this crate runs; mirrors
  /// `tables::program::MAX_LOG_HEIGHT`'s role exactly, one size smaller since private inputs
  /// are typically far shorter than programs.

  pub fn input_log_height(n: usize) -> u8 {
      super::pad_height(n + 1, MIN_HEIGHT).trailing_zeros() as u8
  }

      fn width(&self) -> usize { WIDTH }
  }

  impl<AB: AirBuilder + InteractionBuilder> Air<AB> for InputAir
  where
      AB::F: Field,
  {
      fn eval(&self, b: &mut AB) {
          let m = b.main();
          let v = |i: usize| -> AB::Expr { m.current(i).unwrap().into() };
          let n = |i: usize| -> AB::Expr { m.next(i).unwrap().into() };
          let one = AB::Expr::ONE;

          b.assert_bool(v(IS_REAL));
          // Real rows form a prefix — once IS_REAL drops to 0 it never returns, so the real-row
          // set is always exactly {0, .., realCount-1} for some realCount, never a scattered set.
          b.when_transition().assert_zero((one.clone() - v(IS_REAL)) * n(IS_REAL));
          // IDX = row index: 0 at row 0, +1 every row (including through padding — harmless,
          // nothing reads a padding row's IDX since its count is forced to 0 below). Unlike
          // `program`'s PC (which needs an external `base_pc` anchor), input indices always
          // start at 0 by definition, so no separate "no aliasing without a trusted base" check
          // is needed beyond this.
          b.when_first_row().assert_zero(v(IDX));
          b.when_transition().assert_zero(n(IDX) - v(IDX) - one.clone());
          // AGENTS.md invariant 1: pin the message columns on padding rows too.
          b.assert_zero((one.clone() - v(IS_REAL)) * v(WORD));
          // AGENTS.md invariant 2: MULT_READ forced to 0 on padding rows explicitly — the total
          // provided count below already zeroes out via the IS_REAL factor regardless of
          // MULT_READ's value, but a stray MULT_READ on a padding row is exactly the kind of
          // "unconstrained column nothing currently reads" AGENTS.md's ALU lesson warns about;
          // this local pin is also what makes cheating test (e) (below) a real rejection rather
          // than a no-op tamper.
          b.assert_zero((one.clone() - v(IS_REAL)) * v(MULT_READ));

          let count = v(IS_REAL) * (one + v(MULT_READ));
          bus::INPUT_WORD.table_entry(b, [v(IDX), v(WORD)], count);
      }
  }

  /// How many times each committed index is actually consumed by a `READ_INPUT` — the honest
  /// `MULT_READ` values `input_trace` needs. `idx` is always `< n` for an honest execution
  /// (`emulator::execute` already errors `ExecError::InputIndex` otherwise), so this never
  /// indexes out of bounds on a witness that got this far.
  pub fn read_counts(n: usize, events: &[CycleEvent]) -> Vec<u32> {
      let mut counts = vec![0u32; n];
      for e in events {
          if let Some(Syscall::ReadInput { idx, .. }) = e.sys {
              counts[idx as usize] += 1;
          }
      }
      counts
  }

  pub fn input_trace(inputs: &[u32], read_counts: &[u32], height: usize) -> RowMajorMatrix<F> {
      assert!(inputs.len() <= height, "input table needs {} rows, height {height}", inputs.len());
      assert_eq!(inputs.len(), read_counts.len());
      let mut v = F::zero_vec(height * WIDTH);
      for (i, (&w, &rc)) in inputs.iter().zip(read_counts).enumerate() {
          let r = &mut v[i * WIDTH..(i + 1) * WIDTH];
          r[IDX] = F::from_u32(i as u32);
          r[WORD] = F::from_u32(w);
          r[IS_REAL] = F::ONE;
          r[MULT_READ] = F::from_u32(rc);
      }
      for i in inputs.len()..height {
          v[i * WIDTH + IDX] = F::from_u32(i as u32);
      }
      RowMajorMatrix::new(v, WIDTH)
  }
  ```

  ```rust
          for k in 0..4 { if blk.active[k] { input[k] = Val::from_u32(blk.words[k]); } }
          Poseidon2Event { input, output: blk.state_out }

              for k in 0..4 { if active[k] { input[k] = Val::from_u32(words[k]); } }
              Some(Poseidon2Event { input, output: state_out })
          }
          _ => None,
      }).collect();

      let hc = program.digest();
      let hin = crate::hash::input_digest(inputs);

          program: program_t, cpu, memory, alu, range: range_t, nibble: nibble_t, poseidon2: poseidon2_t, input: input_t,
          public_values: public_values(program.base_pc, tier.0, &exec.outputs, &hc, &hin),
  ```

### Ambiguities resolved (and how)

- **The spec's §2 prose says reads "go through the memory table against that space (`space = 2`, read-only...)"; the binding Task 3 decomposition instead specifies a standalone `input` table and `INPUT_WORD` bus, with `SYS_READ` consuming directly from it.** Followed the Task decomposition literally (it is marked binding; the design-spec prose is background, and the task list's own wording — "a new witness table `input`... PROVIDES `(IDX, WORD)` on a new `INPUT_WORD` bus", "SYS_READ rows CONSUME... from `INPUT_WORD`" — leaves no ambiguity about which mechanism to build). No `memory.rs` changes are needed under this reading; `docs/02-tables-and-buses.md`'s `memory` section is untouched by this plan. Noted so a reviewer comparing this plan against the design spec's §2 prose doesn't read the difference as an oversight.
- **"An index ≥ n_in cannot be satisfied... the emulator must error `InputOutOfRange` for parity."** `emulator.rs` already has `ExecError::InputIndex(u32)`, raised exactly when `arg0 as usize >= inputs.len()` (i.e. `>= n_in`, since `n_in` is defined as `inputs.len()` throughout this plan) — the exact behavior the spec asks for, under a name that already exists and is used elsewhere (`tests/`, no call sites reference a not-yet-existing `InputOutOfRange`). Kept the existing name rather than adding a second, functionally identical variant or renaming a public enum for no behavioral change; called out explicitly in Task 3's Global Constraints and here so it doesn't read as a missed requirement.
- **Whether `IS_INDIGEST`'s final-encoding gadget should reuse `DHVL0..31`/`DHIMAX0..3`/`DINV0..3` (saving 40 columns, since `DIGEST_LAST` and `INDIGEST_LAST` are mutually exclusive in time) or get its own copy.** Chose a separate copy (Task 3 Step 3a's comment states the reasoning): reuse would require re-deriving every `digest_last`-gated pin in the existing code to also branch on `indigest_last` and pick which `pv` slice to write, in already-dense, heavily cross-referenced code — a real risk of a subtle gap for a column-count saving this table's degree/height budget does not need. The task instruction to "mirror the program-digest mechanism exactly" supports treating this as a second, parallel region rather than a generalized one.
- **`verifier_key`'s key shape** — a 3-tuple `(tier, program_log_height, input_log_height)`, not a folded single value (spec explicitly left this open) — decided in Task 3's Interfaces block with the reasoning (two independent, unrelated height parameters; folding would obscure, not simplify).
- **Where in `chips()`/`Traces` the new `Input` chip goes** — appended last (after `Poseidon2`), matching every prior milestone's own convention of appending new chips at the end to avoid disturbing the `i == 1` (`Cpu`) public-values-slot convention `prove_traces`/`verify` hard-code.

## Fullnode sync note (Task 4, Step 6)

`research`'s vendored copy lives in `randprotocol/fullnode`; this note is
for whoever next syncs that copy forward past this plan's changes. It does
not touch the fullnode repo itself — that sync is a separate, later piece
of work.

- **`tables::cpu::pv::NUM` is now 26 (was 18).** Fullnode code that reads
  `Proof::public_values` by fixed offset for `HC0..7` is unaffected — those
  offsets (10..17) did not move, since `pv::IN0..7` were appended after
  them, not inserted before. Code that validates `public_values.len() ==
  18` must be updated to accept 26 instead.
- **`Proof` gained a new field, `input_log_height: u8`,** serialized via
  the struct's existing `#[derive(Serialize, Deserialize)]` — this is a
  wire-format change (see the hard-fork note below).
- **`Machine::verifier_key`'s key shape grew from a 2-tuple to a 3-tuple**
  (`(tier, program_log_height)` → `(tier, program_log_height,
  input_log_height)`), and `log_ext_degrees`/the degree-bits check inside
  `verify` now take the input table's declared height as a third
  parameter alongside the tier and program height. Concretely, the
  fullnode's `deploy/sync-zkvm.sh` injects a wrapper by a Python
  `str.replace` anchored on the exact `verifier_key` signature line;
  after M4.1 that anchor is:
  ```
      pub fn verifier_key(&self, tier: Tier, program_log_height: u8, input_log_height: u8) -> Arc<CommonData<Config>> {
  ```
  and the wrapper to inject is `pub fn log_ext_degrees_pub(&self, tier:
  Tier, program_log_height: u8, input_log_height: u8) -> Vec<usize> {
  self.log_ext_degrees(tier, program_log_height, input_log_height) }`. A
  stale anchor (still matching the old two-argument signature) makes
  `str.replace` a silent no-op — the script exits 0 and prints "synced" —
  and the build then fails downstream with "no method named
  `log_ext_degrees_pub`" instead of failing at sync time. The executor's
  `verify_call` degree-bits check and its `warm` (verifier-key warmup)
  path must both pass `proof.input_log_height` (or the input height for
  the record being verified/warmed) alongside `tier`/`program_log_height`
  anywhere they build or look up a `verifier_key` or call the injected
  `log_ext_degrees_pub` wrapper — the same pattern the tier and program-
  height parameters already followed when M3.4 added the second one.
  `verifier_key` itself still returns `Arc<CommonData<Config>>`; only its
  argument list grew from two to three.
- **`Machine::verify(hc, proof)`'s signature is unchanged** — call sites
  need no source edit, only a recompile against the new `Proof`/`pv`
  shapes (both the extra `input_log_height` field and the wider
  `public_values`).
- **The sync copies `tests/` wholesale but excludes `src/guests.rs`.**
  `tests/e2e.rs` now calls `guests::compiled::fib()` with
  `include_bytes!` of `guests-compiled/bin/fib.bin` — the fullnode must
  either add a `compiled` module and vendor the `.bin`, or exclude the
  two compiled-fib tests.
- **The executor must call `Machine::prove` (fresh salt), never
  `prove_salted`, or hiding is lost.**
- **This is a hard fork.** Old proofs (18 public values, no
  `input_log_height` field) do not deserialize into the new `Proof` shape
  and vice versa; nodes must upgrade in lockstep, exactly as
  `docs/superpowers/specs/2026-09-11-zkvm-m4-design.md`'s §6 ("What does
  not change") anticipates for M4.1 ("`Machine::verify(hc, proof)` (only
  `pv::NUM` grows in M4.1) ... a constraint-set change and therefore a
  hard fork when vendored").
